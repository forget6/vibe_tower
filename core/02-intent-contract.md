# 02. 意图契约与质量保障（VibeContract & FlowCheck）

> 理论支撑：P1（VibeContract）、P2（FlowCheck）
> 对抗失效：**F3 隐性逻辑错误**、**F2 静默规格漂移**
> 落地阶段：Phase 1（契约骨架）、Phase 2（契约生成与断言）

## 1. 目标

把"代码生成了，但不知对不对"变成"**先有可判定的对照基准，再生成代码**"。
契约是本塔最核心的锚：**没有契约，就没有"对错"**。

## 2. 核心机制

### 2.1 任务序列解构（Task Sequence Decomposition）

高阶自然语言意图 **MUST** 先被拆为**有序任务序列**，再逐项生成契约。

| 步骤 | 动作 | 约束 |
|---|---|---|
| 1 | 把一句需求拆为可独立验证的任务（一句话最多一个验证点） | MUST 拆到"能单独失败"的粒度 |
| 2 | 排序：先骨架后边缘，先高风险后低风险 | MUST 与 `01-spec-engine.md` 的切片协议一致 |
| 3 | 标出**不可判定项**（含主观词的目标），就地要求澄清 | NEVER 用默契填补不可判定需求 |

### 2.1a 命令式 → 可验证目标（★v0.7）

> 来源：外部公开实践准则（Karpathy 对 LLM 编码陷阱的观察）。
> 机制依据：**强的成功判据让执行者能独立闭环；弱判据（"让它能跑"）只会换来反复澄清**。
> 因此"做什么"的指令 MUST 先被改写为"用什么判据算做完"。

| 原指令（命令式） | 改写为（可验证目标） |
|---|---|
| "加校验" | "为非法输入写断言，然后让断言通过" |
| "修这个 bug" | "写一条能复现它的断言，然后让它转绿" |
| "重构 X" | "重构前后断言全绿" |
| "优化性能" | "给出前后对照指标，并断言不劣于基线" |

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| 判据先行 | 每个任务 MUST 先给出**可执行的成功判据**（可被机械判定） | 无判据 ⇒ 不得开工 |
| 逐步带验证 | 多步任务 MUST 输出 `步骤 → 验证：<判据>` 形式的计划，逐步带验证点 | 缺验证点 ⇒ 违反 |
| 判据强度自检 | 判据 MUST 强到"可独立闭环"（执行者能自判是否达成）；弱判据 MUST 补强 | 保留弱判据 ⇒ 违反 |
| 命令式残留 | 计划中 MUST NOT 只写"做什么"而无"怎么算做完" | 违反 ⇒ 回炉 |

> 与 §2.3 的分工：§2.3 管"契约 → 断言"的**产物**，本节管"任务**入口**如何被改写" —— 保证断言在源头上就存在。

### 2.2 任务级契约（Task-Level Contract）

每条契约由五个必填槽位构成：

| 槽位 | 含义 | 硬性约束 |
|---|---|---|
| 输入（Input） | 接受什么、拒绝什么（含边界值） | MUST 覆盖空/超界/非法三类；**MUST 穷举合法输入形态**（含简写/限定/全限定等变体），未列举形态视为未定义（★v0.2） |
| 输出（Output） | 产出什么、形态与取值范围 | MUST 可机械比对 |
| 约束（Constraints） | 必须遵守的规则与限制 | MUST 引用规则编号（见 `03-active-rules.md`） |
| 行为属性（Behavior） | 允许与禁止的行为（幂等/顺序/权限/并发） | MUST 可判定；禁止模糊词 |
| 失败语义（Failure） | 出错时的表现与错误分类 | MUST 明确"不做什么"（不得静默降级）；**回落/兜底 MUST 成套**（见 §2.2a，★v0.9）；**无解约束 MUST 声明豁免路径**（★v0.2） |

### 2.2a 输入域与枚举域穷举（★v0.2）

> 来源：真实缺陷回溯（`extensions/05` 机制一）—— 契约只声明"接受某字段"，未穷举其合法形态，
> 实现便各自解释，导致**同一份输入在不同规则下被解析成不同结果**；而枚举缺项时若"静默跳过"，
> 相关规则会**静默失效**（不报错、不命中、无人知）。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| 形态穷举 | 输入/字段的**全部合法形态**（含简写与限定形态、大小写、引号与转义变体）逐一列出 | MUST 穷举；未列举者视为未定义 |
| 枚举兜底 | 类型/枚举/白名单类约束 MUST 有**未识别兜底**：告警或报错 | MUST NOT 静默跳过（静默跳过 = 规则静默失效） |
| 反向枚举 | 明确列出**不接受**的形态（至少一类） | MUST 列出拒绝形态 |
| **降级/回落成套**（★v0.9） | 当输入缺失/不可识别而**回落到另一种形态**（兜底 / 默认 / 兼容路径）时，MUST **连同该形态的配套要素一起回落**（单位、编码、时区、格式与版本、字段集等 MUST 成套） | **只回落一半 ⇒ 违反**（产出"半旧半新"的混合形态：任一侧都不自洽，却常能同时骗过两侧校验）；**无法成套 ⇒ MUST 拒绝产出或显式报错**（MUST NOT 猜、MUST NOT 凑） |
| **枚举扩张 MUST 附「分流点扫描清单」**（★v0.58） | 任何"类型码 / 状态 / 事件"枚举**新增取值**时，MUST 先产出该枚举的**分流点清单**（标签文案 · 任务 / 动作分发 · 列表呈现（脱敏 / 标记）· 详情视图 · 渲染分流 · 兜底 / 默认分支），并**逐点**给处置（分支 / 显式守卫 / 排除） | 任一点缺席即视为**未完成**（新取值在某些分支上"消失"或落默认分支） |
| **远端分发能力的版本不足 MUST 可识别**（★v0.92） | 能力被**分发**到远端执行（脚本 / 边车 / 插件 / 代理）时，调用方 MUST 以**稳定标记**（结构化输出 / 退出码 / 能力声明）识别"远端版本不足"，并给出**可操作提示**（点名缺哪个能力、需升级什么） | 以默认值 / 空值**静默降级** ⇒ 违反（与本节"只回落一半"同族：使用者以为能力已生效，实际未执行）；只回"失败"而不给可操作原因 ⇒ 违反（调用方无法自助修复） |
| **相等比较型校验的空值语义 MUST 显式定义**（★v0.93） | 以"**某值 == 期望值**"为通过条件的校验（白名单 / 配置比对 / 身份或租户核对 / 版本或能力匹配），MUST 显式声明**两端为空 / 缺省 / 缺失**时的结论（**拒绝**或**声明的降级**），MUST NOT 由相等比较**兜底**；期望值来自**配置**时，配置缺省 MUST 在启动 / 装配期 **fail-closed** | 两端**都可为空**而按相等放行 ⇒ 违反（`空 == 空` 恒真 ⇒ **校验被静默跳过**：无日志、无报错、全量用例可全绿）；只校验其中一端 ⇒ 违反（另一端缺失即绕过） |
| **能力边界类前置校验 MUST 定义次序且在动作之前**（★v0.93） | 一次调用可能命中**多个**独立失败点时，环境 / 权限 / 目标这类**能力边界**校验 MUST 在**输入解析与本地 IO 之前**完成（或与之同批一次性给出结论），MUST NOT 让"较晚的、与前者无关的失败"抢先报出 | 早失败被晚失败**掩盖** ⇒ 违反（使用者收到无关错误 ⇒ 误判能力边界合法并继续排查错方向）；同一输入在不同实现顺序下给出**不同错误** ⇒ 违反（口径不唯一） |
| **生成式 DSL 的派生标识符 MUST NOT 裸用保留字**（★v0.94） | 拼接 / 模板生成的 DSL（查询语言、正则、配置表达式、迁移脚本、报表表达式）里，**派生标识符**（列别名 / 表别名 / 键名 / 变量名）MUST NOT 裸用目标 DSL 的**保留字**（MUST 转义或改名） | 裸用保留字 ⇒ 违反（运行时解析才报词法错误，静态编译 / 不执行 DSL 的单测**全绿** ⇒ 静默失效）；靠"人工记得加引号" ⇒ 违反（MUST 有机械卡口扫保留字集合，命中即红，MUST NOT 靠记忆） |

> ★v0.9 补（真实缺陷回溯，`extensions/05` 机制一）：**回落/兜底也是一种"降级"** —— 而"降级"必须**成套**。
> 反例（去业务化）：某标识生成器在"输入不合规"时**回落到旧式前缀**，却仍套用**新式后缀** ⇒ 产出两者拼接的畸形标识；
> 两侧校验各自只看自己那半，故**都判"通过"**。此即"静默降级"的判定化形态：**不是不产出，而是产出了不自洽的组合**。
> 与 §2.2 的分工：§2.2 管"整体把需求做一半"，本节管"**回落到另一种形态时只回落一半**"。

### 2.2b 口径唯一性（★v0.2）

> 来源：真实缺陷回溯 —— "长度/计数/截取"类判定未声明唯一口径，实现各取一义
> （是否含前缀、是否含分隔符、是否忽略大小写），于是**同一事实得出两种结论**。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| 口径声明 | 凡涉及**计数/比较/截取/包含**的判定，MUST 声明唯一口径与边界 | MUST 声明；禁止留给实现默认 |
| 口径可验 | 口径 MUST 能用一条断言表达 | MUST 可机械判定 |
| 口径一致 | 同一概念在同一系统内 MUST 只有一种口径；多处需要时引用同一处声明 | NEVER 复制后各自修改 |
| **更新语义**（★v0.5） | 部分更新类契约 MUST 声明「未提供」与「显式置空」的区别（未提供 ⇒ 保持原值，MUST NOT 写成空） | 未声明 ⇒ 违反（表单未回填即覆盖/清空） |
| **列表 vs 详情**（★v0.4） | 同一实体在**集合/列表**与**详情**两类接口上的字段口径 MUST **显式声明**（明确"哪些字段只在详情回传"），并由**单一真源**承担 | 任一处各自实现 ⇒ 违反（改一处漏一处即偏差） |
| **锁定项三处强制 + 缺省从自述派生**（★v0.66） | 被系统**锁定**的判据项（如"语法不合法""删库"）MUST 在**判定 / 缺省 / 写入**三处口径一致：① **判定侧锁定优先** —— 库列 / 调用方显式配置 MUST NOT 赢回；② **缺省 MUST 由该项自述派生**（MUST NOT 硬编码为宽松侧）；③ **写入侧**（界面 / 接口 / 播种）MUST 拒改或纠正；④ 历史**存量分叉** MUST 有自愈路径（限定"未被人改过"的行 + 逐行留痕 + 不阻塞主流程） | 只落一处 ⇒ 真机缺陷形态：库里写着"可强制"、界面照旧可点、照旧被强制放行；缺省硬编码 ⇒ **新增项漏进名单即静默变宽松**（与 `H5` 分叉 / `H14` 不可定位配套） |
| **多态自述优先于中心分发**（★v0.63） | 类型 / 种类特有的判定 MUST 由**该类型自述**（新增类型 = 只加实现）；按类型枚举的**中心 `switch` / `if-else` 分发** MUST 收敛为「自述 + 一层分派」，且**新增一个类型时中心代码的 diff MUST 为空**；遍历（树 / 集合 / 清单）MUST 只有**一份**实现（MUST NOT 各写各的递归）；卡口 MUST 断言「按类型列举的分支计数 MUST NOT 回升」 | 新增类型**必漏改**中心代码 ⇒ **静默**漏判 / 缺字段（"看起来只是文案少了一截"）；同一容器多份遍历 ⇒ 同一输入得出不同结论（与 `extensions/04` §2.2b「卡口扫描面 MUST 与不变量等宽」配套：不变量与其扫描面 MUST 同宽） |
| **可复现产物的指纹口径**（★v0.78） | 凡声明「**可复现**」的产物（二进制 / 包 / 镜像 / 快照），其构建 MUST **固定指纹种子**（如 build id；时间戳等易变项 MUST 外置）；MUST 留「**同一提交状态重建两次 ⇒ 同指纹**」的**可复跑证据**，并把指纹登记在**单一真源**（版本档 / 校验清单） | 声称"可复现"却不固定种子 ⇒ **声明与事实分叉**：同源重建得不同指纹而**无人报错**（与 `H1` 静默兜底同族）；指纹散落多处 ⇒ 改一处漏一处（本节**产物面**形态） |
| **临时口径的显式标注**（★v0.78） | 因外部约束**临时**收敛的口径 MUST 显式标注「**临时**」并写明**生效范围 / 失效条件**；被后续口径覆盖时，**新条目 MUST 写明"覆盖了谁"**，历史条目 **MUST NOT** 回改（就地留痕） | 把临时约定写成长期契约 ⇒ 下一位执行者**照已废规则动手**（本节**时间维**形态）；不写"覆盖了谁" ⇒ 读者无法判断哪条有效（与 `extensions/05` 教训沉淀配套） |
| **共同加工单施加点**（★v0.12） | 对**所有分支**都成立的加工（装饰 / 归一化 / 脱敏 / 权限标注 / 类型标签 / 审计埋点 …）MUST 施加在**分派点之前**且**只有一处**；MUST NOT 写在某一条分支之内 | 分支内施加 ⇒ 违反（未覆盖的分支**静默缺字段**，下游兜底把它显示成"未知/空" —— **表象与根因相距很远**） |

> ★v0.12 补（真实缺陷回溯，`extensions/05` 机制一）：**"同一事实"不止指同一条口径被复述，也包括"对全部分支都成立的加工"**。
> 反例（去业务化）：某接口在**一条分支内部**回填类型标签 ⇒ 其余分支该字段恒为空；下游以 `|| 默认值` 兜底，
> 于是"未覆盖"被显示成"未知/空"，而**列表**（另一条渲染路径）显示正确 ⇒ 同一事实两处不一致，且**无任何信号**。
> 判定要点：加工 MUST 落在**分派之前**的**唯一施加点**（新增分支时天然继承），MUST NOT 依赖"逐分支补装"。

### 2.2c 无解规则禁令（★v0.2）

> 来源：真实缺陷回溯 —— 某约束在**平台语义下根本不可能满足**（例如平台明令某场景不允许某个可选属性），
> 该规则即"无解"：不豁免就会把所有合规输入一并拦下，等于用规则制造故障。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| 可满足性检查 | 起草规则前 MUST 验证"目标场景下该约束是否可满足" | MUST 验证；不可满足 ⇒ 不得作为规则 |
| 豁免路径 | 不可满足场景 MUST 走**显式豁免**，并记录"为何豁免" | MUST 记录理由；NEVER 静默豁免 |
| 失败语义 | 失败语义 MUST 覆盖"约束与平台语义冲突"时的行为 | MUST 明确，不得留空 |

### 2.2d 结果语义三值化（★v0.6）

> 来源：真实缺陷回溯（`extensions/05` 机制一）—— 两类**成对出现**的语义混同：
> ① **"未命中"被当成"失败"**：以"错误对象是否为空"反推存在性 ⇒ 判断恒真/恒假，幂等与查重分支形同虚设；
> ② **"看起来成功"被当成"成功"**：跨边界的成功信息不统一，一侧判成功、另一侧判失败；或把成功判成失败 ⇒ 触发重复执行。

结果 MUST 三值明确，禁止压成两值：

| 值 | 语义 | 硬性约束 |
|---|---|---|
| 命中 | 目标存在且已取得 | 命中与未命中 MUST 由**同一处判据**区分 |
| 未命中 | 目标不存在（**正常结果**，不是错误） | MUST NOT 与失败混同（未命中 ⇒ 走正常分支或返回显式空结果） |
| 失败 | 调用/解析/写入出错 | MUST 带可分类错误并留痕；MUST NOT 被吞成"未命中" |
| 要求 | 内容 | 硬性约束 |
|---|---|---|
| 判据单真源 | 存在性/成功性判定 MUST 收敛到一处纯函数或一处状态标记 | MUST NOT 以"错误对象为空"反推存在（同名错误与"查不到"必须可区分） |
| **诊断面与判定面的遍历口径 MUST 显式分离**（★v0.62） | 同一批输入上的两类面 MUST **各自声明**遍历口径：**诊断 / 展示面** MUST **全量**（每项都产出条目，MUST NOT 因先出现的错误短路）；**判定 / 执行面** MUST **从严**（首错即拒，fail-closed）；一面的"全量" MUST NOT 被顺带实现为另一面的行为 | 为"给全清单"把判定面也改成**全量继续** ⇒ 把未知错误带进生产；为"从严"让诊断面在首错停下 ⇒ 使用者拿不到完整清单（两面各违反一条） |
| 成功标记一致 | 跨边界（进程/脚本/服务）的成功判定 MUST 以**两侧逐字一致**的显式标记为准，且**优先于通用的失败判定** | 标记不一致或未优先 ⇒ 违反（远端已成功却被判失败） |
| 失败必留痕 | 失败路径 MUST 写日志或审计；MUST NOT 静默吞掉 | 静默失败 ⇒ 违反 |
| 重复执行防护 | 已进入终态的对象 MUST NOT 因判定混同而被再次执行 | 违反 ⇒ 阻断（与"幂等"成对） |
| 读回核验（★v0.8） | 跨系统**写操作**的成功判据 MUST 取自**目标系统可读回的状态**（执行后查询目标侧），MUST NOT 只看调用返回/退出码 | 只凭返回值宣告成功 ⇒ 违反（"假成功"） |

| **旁路副作用 MUST 与主流程成败解耦**（★v0.58） | 主流程**已成功落库 / 已生效**之后才执行的旁路动作（审计留痕 / 通知 / 指标上报），其失败或异常 MUST NOT 改变主流程的响应语义（MUST NOT 回 5xx、MUST NOT panic），但 MUST 记 ERROR（可排查） | 旁路失败**反噬主流程**（已成功却报错）或**静默**（无任何留痕）⇒ 违反 |
| **声明面与实现面 MUST 对称**（★v0.60） | 任何**声明过的行为**（设计文档 / 源码注释 / 接口或界面入口 / 配置开关 / 字段）MUST 同时具备 ①**实现面**（可指到的调用点）与 ②**判据面**（可复跑的卡口）；**只声明不实现**、**只有设施没有消费方**（字段无消费方 / 状态无迁移 / 入口无末端处置 / 分支为空壳）MUST 视为缺陷（"半实现"） | 声明被当作事实引用 ⇒ 所有下游按"已实现"行动，缺口无人核对（真实反例：文档承诺"两条失败路径同档 fail-closed"，实现只落地其中**一条** ⇒ 另一条静默放行；设计要求"输入位置追踪 + 期望输入报错"，实现只有**一半** ⇒ 使用者拿到结论却无从定位） |
| **产出端与消费端 MUST 逐出口 / 逐入口对齐**（★v0.82） | 声明「某事实取自**某个执行输出**」时 MUST **双向**对齐到同一集合：① **每个**会产生该输出的执行出口 MUST 都产出它（标记 / 键名 / 取值口径一致）；② **每个**写入或使用该事实的入口 MUST 都**消费**它，**MUST NOT 猜测 / 兜底 / 取默认值**（取不到 ⇒ 按「不可判定」处理，见本节三值化），任一侧缺位都算半实现（与上一行同族，**不新立机制 / 不新增编号**） | 只在一侧补齐 ⇒ 违反：未产出的那条路径让取值落成"猜"，猜出来的值又被当作事实写进记录 ⇒ 记录与实际**长期分叉且无人报警**（真实反例：记录字段的注释声明"取自执行输出"，两条执行路径只有一条产出它，写入入口也未读 ⇒ 全链路卡口绿色，该字段的值实际由默认值承载） |
| **审计结论 MUST 落到代码**（★v0.60） | 归因 / 取证完成后 MUST **当场**改代码修复，**或**显式登记为"待裁定选项"（含代价与影响）；MUST NOT 以"已审计 / 已报告 / 已出清单"收尾 | 停在报告 ⇒ 违反：同一缺陷在下一轮以**另一形态**复发，且无人知道它**从未被修**（"审计完就不管了"） |
| **「本轮已执行且判否」MUST NOT 与「本轮未执行」同形**（★v0.98） | 采集 / 探测类循环的结果写入 MUST **每轮反映本轮结论**（含结论与可陈述原因），MUST NOT「仅在状态翻转时写」—— 翻转式写入使「本轮未执行」与「执行了且结论为否」在存储层**完全同形**，既无法区分故障面，也无法验证采集是否真的覆盖到该对象；同一能力的**实现链分段**（探测 / 取数 → 落库 / 写回 → 展示 / 输出）MUST **同轮逐段核对**，MUST NOT 只修现场暴露的那一段；展示 / 输出面 MUST 保留三值（成立 / 不成立 / **未判定**），MUST NOT 用默认值把「已判定为否」并入「未判定」（与本节 ★v0.57 互为镜像） | 翻转式写回、默认值合并、或只修链上暴露的一段 ⇒ 违反：判据全绿、页面长期显示「未知 / 默认」，而结论其实早已算出（真实反例：同一能力的协议段已按类型分派修好，落库段仍「翻转才写」导致失败零痕迹，展示段仍 `ELSE 默认值` 把已判定的"否"显示成"未知" ⇒ 用户二次报障，现象与首次不同，难被认成同族） |
| **载口径：结论按主体口径、原因只需可达**（★v0.99，承接上一行） | **结论** MUST 按**主体口径**写入（MUST NOT 为「留痕」每轮重写热点行 —— 其变更时间戳会被采集循环覆盖，同一字段静默变成第二种语义）；**原因** MUST **可达**，载体不限（判定面返回值 / 日志 / 只读查询接口皆可），MUST NOT 强制落到主体行；MUST NOT 以「可观测性」为由新增主体表字段（与上一行互补：上一行管「不许同形」，本行管「不许为消同形而改契约」） | 为让原因可见而给主体表加诊断列、或让采集循环每轮重写主体行 ⇒ 违反：存储契约被「只该影响少数行」的功能改宽，热点行的变更时间戳被覆盖成「最后采集时间」（真实反例：按「原因必须进同一次入库」实现 ⇒ 加列 + 每轮写 ⇒ 下一轮必须整版撤回） |
| **声明的周期 MUST 与单轮能力自洽**（★v0.99） | 定时 / 周期类循环（调度 / 采集 / 巡检 / 批处理）声明的**周期 MUST 覆盖单轮最坏耗时**，否则须改并发或**显式声明降级**（MUST NOT 让 ticker 丢 tick 而对外仍称"每 N 分钟一轮"）；慢轮 MUST 有**单轮预算**（< 周期）且预算耗尽时剩余对象 MUST 计入「未覆盖」并**出声**（MUST NOT 静默跳过）；并发化 MUST NOT 改变写入口径（承接上一节「本轮已执行且判否 MUST NOT 与本轮未执行同形」） | 周期承诺与实现能力不符 ⇒ 违反：声明 10 分钟、实际一轮 45 分钟 ⇒ tick 被静默丢弃、覆盖范围不可证；无预算 / 无未覆盖计数 ⇒ 「跑不完」在日志与统计里**都不存在**（真实反例：单协程 + 每对象错峰 5s，对象数从数十涨到数百后一轮远超周期，页面仍显示"每 10 分钟"，缺失对象既不在日志也不在统计） |
| **分层响应的成败判定 MUST 逐层穷举**（★v0.91） | 对**多层结构**的响应 / 结果（外层信封：状态码 / 错误码 / 消息；内层：明细项数组 / 子结果），成败判定 MUST **逐层**参与：① **外层信封 MUST 参与判定**，MUST NOT 只扫内层明细项；② **任一层**判失败即失败，MUST NOT 由「内层项全成功 / 内层为空」覆盖外层失败；③ 层间 MUST NOT 互相兜底 —— 某一层取不到 ⇒ 按「**不可判定**」承载（见本节 ★v0.57），MUST NOT 落成「成功」 | 只扫其中一层 ⇒ 违反：外层已报失败而内层为空或内层各项自报成功 ⇒ **整体被判成功**，失败**静默变成成功**且无任何信号（与「假成功」同族，区别在判定的**面缺了一层**而非标记不一致） |
| **依赖故障 MUST 与判定失败分档**（★v0.93） | 判定链上「**依赖不可用**」（外部服务 / 密钥源 / 元数据 / 缓存 / 网络）与「**事实不成立**」（凭据无效 / 值不符 / 未命中）MUST 映射到**不同**的结论与状态码，且**可重试性**MUST 可区分 | 依赖故障被报成"判定失败" ⇒ 违反（排障被指向错方向：使用者去改凭据，而真正原因是依赖未就绪）；两者共用同一状态码 ⇒ 违反（可重试与不可重试无法区分，重试策略与告警分级失效） |

> ★v0.91 补（真实缺陷回溯，两条同源）：**「判哪一层」必须先穷举** —— 跨系统调用的响应常是**多层结构**
> （外层信封 + 内层明细），判定若只扫其中一层，另一层的失败就**无处落地**。
> 反例（去业务化）：① 某推送结果的判定只遍历**明细项**，当外层信封的错误码为负、或传输层状态为 4xx–5xx 时，
> 明细项为空 ⇒ 「无失败项」⇒ 被判**成功**（失败被计成成功，其后的重试与告警全部不触发）；
> ② 同一判定的另一条实现路径只在明细项内比对，外层缺位时用默认值补全 ⇒ 两条路径对同一事实给出**相反结论**。
> 与本节既有行的分工：**「成功标记一致」**管跨边界的标记是否逐字一致、**「读回核验」**管成功判据取自哪一侧、
> **「查不到 vs 查不动」**管查询步骤的三态；本行管**单次响应内部参与判定的层是否穷举**
> （是 §2.2a「输入域穷举」在**响应侧**的镜像：彼管输入形态，本行管判定层次）。
> 判定要点：**每一层要么参与判定、要么显式声明「本层不承载成败语义」**，MUST NOT 静默不扫。

### 2.2e 被跳过的配置必须可见（★v0.32）

> 来源：真实缺陷回溯 —— 配置驱动的装载器对"无法解析 / 校验不通过"的配置行**记一条日志后跳过**；
> 而配置界面仍显示该行"已启用" ⇒ **看起来生效、实际不生效**（静默失效），只有翻服务端日志才能发现；
> 若**全部**行都被跳过，还可能退化成"零规则放行"（安全功能被静默关闭）。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| 跳过即显形 | 装载器跳过任何配置行时，除日志外 MUST 在**配置界面**给出可见标记（无效 / 已跳过 + 原因） | 仅写日志 ⇒ 违反 |
| 三态可判 | 每行配置 MUST 可判定三态：**生效 / 停用 / 无效被跳过** | 只有两态（把"无效"混进"停用"）⇒ 违反 |
| 全量无效兜底 | 若**全部**行无效或停用，装载 MUST 走**显式兜底**并留痕，MUST NOT 静默"零规则放行" | 静默放行 ⇒ 违反 |
| 界面文案来自真源 | 标记与原因 MUST 由装载器回传（界面 MUST NOT 自造判定） | 界面自造 ⇒ 违反 |

### 2.2f 控件空态必须可读（★v0.33）

> 来源：真实缺陷回溯（用户报障原文即"**XX 都不可选了**"）—— 某选择控件在"**前置条件未满足**"时被禁用，
> 而文案仍是**正常态占位语**（"请选择 X"）⇒ 用户看到的只是一个**灰掉的框 + 点不动的按钮**，**不知道下一步该做什么**；
> 同轮另有第二个诱因：下拉的"关闭判定"跨越了**按钮 / 面板**边界（属 `extensions/03` §2.3b 既有形态，此处仅登记不新增）。
> 判定要点：**"未满足前置"与"已满足但候选为空"是两种不同状态**，压成一态即缺陷（与 §2.2d 三值化同源，但落在**控件可读性**上）。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| 空态可读 | 控件处于**空 / 禁用 / 无候选**状态时，MUST 用**文案**说明**原因 + 下一步**（如"请先选择 A" / "当前条件下无可用候选"） | 只靠灰化 / 禁用表达 ⇒ 违反 |
| 三态分离 | "**未满足前置条件**"与"**已满足但候选为空**" MUST 是**两种不同文案**（各自可判定、可断言） | 两态合一（同一句占位语）⇒ 违反 |
| 禁用可解释 | 禁用态 MUST 有**可读原因**（就地文案 **或** 悬浮提示，二者 MUST 至少其一） | 无任何原因 ⇒ 违反 |
| 文案即断言 | 上述各态文案 MUST 由卡口**逐态断言**钉住（改文案即改卡口） | 无断言 ⇒ 违反 |
| NEVER | NEVER 用"**禁用 + 正常态占位语**"的组合代替状态说明；NEVER 让用户在"下一步该做什么"上靠猜 | — |

### 2.2g 规模面无折叠即失真（★v0.35）

> 来源：两轮真实回溯 —— ① 某"多选"能力上限上调后，**已选项被逐名铺开**（触发文案 + N 个标签）⇒ 触发处被截断、标签铺满屏幕，
> **人眼无法核对"到底选了多少、选了哪些"**；② 第一轮修完又发现**折叠的适用面过宽**（把"名字里带数字"的**异构项**也折进区间）
> ⇒ 用户**看不出自己选了哪些具体项**（换个入口就复发）。
> 判定：这不是"排版问题"，而是**结果语义失真**（§2.2d 的一种）—— 「看到的内容」≠「实际范围」时，用户**无法核对**，等于没有告知。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| 规模不放大 | 集合规模增长时，展示 / 交互 MUST NOT **同比例放大**（超阈值即不可核对）；MUST **无损折叠** 或 **分页**，二者至少其一 | 原样铺开 ⇒ 违反 |
| 折叠无损 | 折叠结果 MUST 保留**真实起止项 + 计数**（两端 MUST 是**真实存在的项**，MUST NOT 补零 / 臆造）；MUST NOT 用截断 / 省略号代替折叠 | 省略号 / 截断 ⇒ 违反 |
| 只折同构副本 | 折叠 MUST 只适用于**同构副本**（同一套命名下的编号项）；**异构项 MUST NOT 被折进同一区间**（否则用户看不出选了哪些具体项） | 异构混折 ⇒ 违反 |
| 纯展示 | 折叠 MUST 是**纯展示层**行为：请求 / 接口 / 执行 MUST 收**完整集合**；MUST NOT 让折叠结果进入数据面 | 折叠进载荷 ⇒ 违反 |
| 逐个可达 | 折叠 MUST 保留**逐个查看 / 移除**的入口（展开态或等价能力） | 只能看折叠态 ⇒ 违反 |
| **留痕 / 错误信息同样折叠**（★v0.95） | 留痕 / 错误信息（失败原因 / 诊断文本 / 审计摘要）里的**聚合清单**（未执行 / 已完成 / 命中项）MUST **折叠**（计数 + 范围缩写），MUST NOT 逐项全量拼接写入**定长字段**（否则超限 ⇒ 存储层拒绝写入 ⇒ 状态无法落库 ⇒ 停在**可重试中间态** ⇒ **无限重跑**） | 全量拼接写入定长留痕字段 ⇒ 违反（写失败 ⇒ 状态机卡死 + 无限重跑）；折叠 MUST 无损（真实起止项 + 计数） |
| **载体容量 MUST 写入侧判定**（★v0.92） | 写入**定长 / 有上限**的持久化载体（字段长度、消息体、请求体、缓存条目等）前，MUST 显式判定载荷是否超限；超限 MUST 走**声明的降级**（无损裁剪 + **可见标记**）或**显式失败**，MUST NOT 依赖存储层截断 | 依赖存储层 / 传输层截断 ⇒ 违反（严格模式报错 ⇒ 功能完全不可用；非严格模式**静默截断** ⇒ 载荷成为**非法结构** ⇒ 下游解析静默失效，且与"无值的正常状态"**不可区分**）；降级 MUST 带可见标记（MUST NOT 让使用者以为看到的是全部） |
| **全量承诺 MUST 用取尽证明**（★v1.00） | 凡声明"**全量 / 全部 / 所有**"的检索、遍历或导出，终止条件 MUST 是**取尽条件**（键集 / 游标推进到底、无下一页、计数闭合），MUST NOT 复用**分页页大小**作为总数上限；且 MUST 与一份**独立计数**对账（声明数 vs 实取数），差额 MUST 以**可见信号**呈现（日志 + 状态位） | 拿页大小当全量上限 ⇒ 违反（大表长期只处理前 N 条，且"取到上限"与"刚好取完"在返回值 / 日志上**不可区分**）；无计数对账 ⇒ 违反（少取无声） |
| NEVER | NEVER 用"看起来整齐"掩盖"实际范围"；NEVER 让用户**无法核对**自己操作的作用面；NEVER 用"页大小恰好够"冒充"已经取完"（★v1.00） | — |

> ★v1.00 补（真实缺陷回溯，去业务化）：某"全量同步"实现**声明**拉全表，**实取**写成 `ORDER BY 主键 LIMIT <页大小>`；
> 页大小与常见表规模同量级 ⇒ 大表长期只同步前一段，而状态位与日志都显示"成功"（用户侧表现为"目标端条目数对不上"）。
> 与本节的分工：既有的"规模不放大 / 折叠无损"管**展示侧**的范围失真；本行管**取数侧**的范围失真 —— 两者同族（「处理范围 ≠ 声明范围」），
> 判据面不同（一个在渲染，一个在终止条件与计数对账）。

### 2.2h 同一语义的多真源 MUST 在分类判据里对齐（★v0.53）

> 来源：真实缺陷回溯 —— 一条"分类 / 分流"判据（决定某操作属于**绝对禁止**还是**可人工放行**）只枚举了**一条**判定路径
> （静态禁用清单），而同一语义还有**第二条路径**（可配置规则表）。实测中规则表**先于**清单命中 ⇒ 本应"绝对禁止"的操作
> 被归入"可人工放行"档 —— **语义被静默放宽**（不报错、不告警，交付物全绿）。首版卡口只覆盖了"实现者想到的那条路径"，
> 因此**抓不到它**；抓到它的是**权威口径**（把"该操作必须拦死"逐字转成用例）。
>
> **★v0.56 增补（"时点"维度）**：另一类真实缺陷回溯 —— 同一张单的"**能不能做**"被判了**两次**：审批时按【当时的规则表】
> 判"可放行"并建单，执行前的复检又按【**执行时**的规则表】重判一次 ⇒ 规则在此期间被收紧 ⇒ 该单在**最后一步**失败
> （用户感知：「**强制提单，链路不通**」）；反之规则被放宽时，已拒的单会**悄悄变可做**。
> 即：多真源不只在**空间**上分裂（哪条路径先命中），也会在**时间**上分裂（哪个时点的真源说了算）。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| 多真源盘点 | 分类判据开工前 MUST 先列出该语义的**全部判定路径**（静态清单 ∪ 可配置规则表 ∪ 各检查项 ∪ 兜底层），逐条命名 | 只列一条 ⇒ 违反（另一条必漏） |
| 逐路径枚举 | 分类结果 MUST 对**每条路径的产出**逐一枚举归属；MUST NOT 只覆盖"实现者最熟 / 最先想到"的那条 | 漏一条 ⇒ 违反 |
| 冲突取严 | 多条路径结论冲突时，分类 MUST 取**更严**的一侧（禁止 > 可放行），且该冲突 MUST 在设计文档**显式登记** | 取宽松一侧 ⇒ 违反（静默降级为"可放行"） |
| 双档反例 | **每个分类档** MUST 至少 1 条真实反例：禁止档给"绕过清单但命中规则表"的输入；放行档给"确实只命中可放行规则"的输入 | 只有单侧反例 ⇒ 违反 |
| 单真源复用 | "某档包含哪些项" MUST 只有**一处真源**；提交侧、执行侧、**放行后的复检侧** MUST 复用同一函数 | 各写一份 ⇒ 违反（改一处漏一处） |
| **结构化载体 MUST 键级写入**（★v0.92） | 同一字段同时承载**结构化载体**与**自由文本**时（结构化文档存于单个字段 / 列），写入 MUST 只更新对应**键 / 子结构**（键级合并），MUST NOT 把自由文本**整段写入**该字段；载体**解析失败**（历史脏数据 / 曾被覆写）时 MUST **fail-closed**（拒绝写入并保留原文），MUST NOT 静默改写 | 整段覆写 ⇒ 违反（原结构化内容被**静默销毁**且**无任何报错**；下游读取方解析失败后多回落"空 / 未记录"，表现为"某个数值永远出不来"）；解析失败仍改写 ⇒ 违反（原文丢失）；与"单真源复用"行的分工：该行管**同一语义在多处被定义**，本行管**同一字段承载两种语义**（写入侧） |
| 决定随单冻结（★v0.56） | 决定"**能不能做**"的判据与其依据 MUST 随单**冻结**（结论 + 依据快照进单据载荷）；后续阶段 MUST 以**冻结口径**为准，MUST NOT 用**当时可变**的配置 / 规则表 **重判同一个决定** | 用后续时点的新真源重判 ⇒ 违反（收紧 ⇒ **已获批**的单在最后一步失败；放宽 ⇒ 已拒的单悄悄可做） |
| 护栏实时例外（★v0.56） | **必然失败 / 不可逆**类护栏 MUST **实时生效**（语法不可解析 · 词法失败 · 前置实体不存在 · 不可逆破坏操作）—— 它们不属于"策略放宽"，MUST NOT 被"冻结口径"覆盖 | 把护栏也交给冻结口径 ⇒ 违反（会放行**不可能 / 不可接受**的操作） |
| 真源变更留痕（★v0.56） | 冻结之后真源若发生变更，MUST 以**不改变本次执行**的方式**显式留痕**（新增命中 / 命中消失） | 静默 ⇒ 违反（事后无法分辨"当时按哪版口径放的"） |
| **已发生事实与状态解耦**（★v0.59） | 凡"**已授权 / 已批准 / 已放行 / 已豁免**"这类**已发生的事实**，其判据 MUST 由**冻结留痕**（依据快照 + 行为人 + 时点）表达，MUST NOT 用"**当前状态**恰好等于某个值"表达；**状态只回答"当前还能不能做"**（领取 / 续跑 / 终态短路 / 提交闸门），与"是否已放行"**各管一段** | 用状态表达已发生的事实 ⇒ 违反：状态会随流程**合法前进**（执行中 / 失败待重试）⇒ 单点判定**必然在某个合法状态上静默失效**（已获批的请求在后续步骤被同一判据拦下） |
| **放行状态族 MUST 显式列举排除项**（★v0.59） | 若判据仍需状态侧输入（"已放行之后"的**状态族**），该族 MUST 定义在**状态真源**处并**显式列举排除项**；★尤其：**驳回 / 取消这类"否定动作"同样会写审批留痕** ⇒ 留痕只证明"有人动过单"，**MUST NOT** 用来推断"已放行" —— 排除项 MUST 由**状态族**承担 | 只靠留痕排除 ⇒ 违反（把"已驳回"当成"已放行"；且留痕一旦被"统一化"该形态必然复发）；排除项未列举 ⇒ 违反（后人无从知道为何需要状态族） |
| NEVER | NEVER 用"清单已覆盖"推定分类完备；NEVER 让"本应禁止"的操作因**另一条路径先命中**而降级为可人工放行；NEVER 用**后续时点**的真源重判**已冻结**的决定；NEVER 用**当前状态**表达**已发生的事实**（授权 / 批准 / 放行）；NEVER 用**审批留痕**推断"已放行"（**驳回同样写留痕**） | — |

### 2.2i 并列的安全类控件 MUST 同款交互，并按风险不对称分级留痕（★v0.55）

> 来源：真实缺陷回溯 —— 同一实体上并列的两个**安全类开关**（"是否启用" / "是否允许人工放行"）若各自发明交互
> （一个即时切换、另一个要进编辑表单），用户会**按错误预期操作**；更隐蔽的是**留痕等级**：把"**放宽**一条限制"
> 与"**收紧**一条限制"写成同一级别日志 ⇒ 事后审计**无法分辨谁放宽过** —— **风险不对称被抹平**。
> 用户口径：「**页面设计参考规则启动按键**」——同页同类控件 MUST 是同一形状。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| 同款交互形状 | 同一实体上并列的安全类控件（启停 / 放行 / 豁免 / 白名单 …）MUST 同款：交互形状（开关 vs 表单）、接口形状（同款 endpoint 与入参）、权限门、失败回滚（以服务端为准） | 各自发明 ⇒ 违反（用户按错误预期操作） |
| 风险不对称分级留痕 | **放宽**类操作（允许放行 / 关闭校验 / 扩大范围）MUST 有**二次确认** + **更高级别审计**（如 WARN）；**收紧**类可用常规级别 | 两者同级留痕 ⇒ 违反（事后无法分辨"谁放宽过"） |
| 只读侧同语义表达 | 无写权限者看到的状态 MUST 与开关**同语义**（如"可强制 / 不可强制"徽标），MUST NOT 只给无语义图标 | 语义缺失 ⇒ 违反 |
| 缺省即安全 | 入参缺省 MUST NOT 被解释为"放宽"；缺省 MUST 取**历史口径**并显式登记 | 缺省 = 放宽 ⇒ 违反 |
| 机械断言 | 每个并列控件 MUST 有"同款形状"断言（同款 endpoint + 同款失败回滚）与"分级留痕"断言 | 无断言 ⇒ 违反 |
| NEVER | NEVER 对"放宽"类操作省掉二次确认或降级留痕；NEVER 让并列控件各自为政（一个即改、一个要进表单） | — |

### 2.2j 返回值容器 MUST 只经访问器读取（★v1.00）

> 来源：真实缺陷回溯（去业务化）—— 某执行器 / 运行器的**返回值容器**（结果对象）当前实现**恒返回非空实例**，
> 于是调用方普遍**裸解引用**它的成员（数十处）。当为可测性给它加**注入接缝**（允许返回零值 / 错误路径返回 nil）后，
> 这条"恒非空"的全局不变量**不再成立**，而裸解引用处**无一有守卫** ⇒ 首个非空之外的路径即崩。
> 判定：这不是"防御式编程过头"，而是**不变量没有被表达** —— 非空性既无断言锚，也无单一读取口，
> 于是它只活在实现者的记忆里，接缝一开即失效。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| 单口读取 | 结果容器（结果对象 / 指针 / 可选包装）的成员 MUST 只经**统一访问器**读取；访问器 MUST 定义 nil / 零值 ⇒ 的**语义**（空串 / 零值 / 零集合），且该语义 MUST 显式声明 | 裸解引用成员 ⇒ 违反 |
| 不变量不得口头 | "当前恒返回非空" MUST NOT 作为免守卫的理由；该不变量若重要，MUST 由**断言**钉住（构造点唯一 / 返回值形状） | 以"现在不会空"免守卫 ⇒ 违反（不变量无人守） |
| 接缝同轮收敛 | 为可测性引入**注入接缝**的同一轮，MUST 把该容器的读取面收敛到访问器；MUST NOT 分批（先开接缝、后补访问器） | 先开接缝后补访问器 ⇒ 违反（中间态可崩） |
| 机械判定 | 结果容器成员的**裸解引用计数** MUST 有上限（0 或显式登记的基线），新增即红；访问器自身 MUST 有 nil ⇒ 零值语义用例 | 无扫描 ⇒ 违反（基线只能靠人记得） |
| NEVER | NEVER 把"当前实现恒非空"当作契约；NEVER 让同一容器的成员在**多个**读取口各写一份兜底（兜底口径会分叉） | — |

> 与 §2.2d 的分工：§2.2d 管**结果语义**（成立 / 不成立 / 未判定）；本节管**结果的读取方式**（不重复判定语义）。
> 与 `extensions/04` §2.2a 的分工：那里管"断言够不够"的静默失效面；本节是"容器形状"的静默失效面。

### 2.3 契约 → 断言（Contract to Assertions）

| 步骤 | 动作 | 约束 |
|---|---|---|
| 1 | 每个契约槽位至少 1 条断言 | MUST 槽位—断言可双向追溯 |
| 2 | 断言先于实现存在，并可执行 | MUST 在 Phase 4 先跑出 RED |
| 3 | 断言变更须记录理由 | NEVER 用改断言的方式"修 bug" |
| 4 | 断言集覆盖：正常路径 + 边界 + 失败路径 | MUST 三类齐备 |

> ★v0.88 补（TDD 铁律：先红后绿，反向演进并入本节 —— C5 合并优先）：表第 2 行的"断言先于实现"由此钉死为**可机械判定的时序** ——
> 没有可复跑的**失败测试证据**（RED）MUST NOT 写任何生产代码；「先写实现、后补测试」MUST NOT（后补的测试天然迁就实现，
> 断言退化为覆盖率摆设，守不住意图）。机械判定：生产代码变更所在提交 MUST 同时含对应测试变更，且该测试 MUST 能**独立复跑**。
>
> ★v0.89 补（重构场景 = 本节的强制适用场景，反向演进并入本节 —— C5 合并优先）：**行为守恒重构**开工前 MUST 先铺**特征测试**
> （锚定**现状行为**：正常路径 / 每个分支 / 边界 / 错误语义），MUST NOT 锚定实现细节；重构单元 MUST ≤ 1 个模式应用点（超了 MUST 拆），
> 每一小步 MUST 过机器验证（gate/全量），连续两小步失败 ⇒ 停止并回退到最近绿点按缺陷四步归因。
> 机械判定：重构提交前特征测试在位且绿；依赖不可离线时 MUST 先开**注入接缝**（行为中性）再铺网，MUST NOT 裸奔重构。
>
> ★v0.93 补（反向演进并入本节 —— C5 合并优先）：**"零副作用 / 零调用"类断言 MUST 自带反向对照**。
> 断言"某动作**没有**发生"（未发请求 / 未写存储 / 未落盘 / 未改状态）时，MUST 同时给出**对照断言**：
> 同参数下**去掉抑制条件**（如去掉"只回计划"的开关）时，该动作**必然发生**（计数 / 标记非零）。
> 反例（去业务化）：某"只回计划、不落库"的开关，其断言只查"落库次数为 0"；而被测路径**根本没被执行**
> （未接线 / 提前返回 / 前置分支吞掉）时同样得到 0 ⇒ 用例**假绿**，与"真的没有副作用"不可区分。
> 补齐对照（不带该开关时必落库）后，断言才具备效力。此为「必不误报」的**对偶面：必不假绿**。

### 2.3a 事实夹具保真：参与比较的字段必须齐（★v0.32）

> 来源：真实缺陷回溯 —— 与**外部事实**做比较的判定，其测试夹具只填了**部分**参与比较的字段；
> 未填字段取零值 ⇒ 比较结论与真实不符 ⇒ 先产出**假失败**（看似"实现漏判"），补齐夹具后又险些放过"真命中"——
> **夹具不全同时污染"命中"与"不误报"两侧结论**，且它伪装成"实现缺陷"，会把排查引向错误方向。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| 字段对齐 | 夹具 / 桩 MUST 覆盖判定**全部参与比较的字段**（含默认值、可空性、长度、精度、单位等） | 少填任一比较字段 ⇒ 违反 |
| 清单驱动 | 断言 MUST 先列出"**比较字段清单**"，再核夹具是否齐（MUST NOT 凭印象） | 无清单 ⇒ 违反 |
| 零值歧义禁令 | 零值 MUST NOT 被当作"该字段不参与比较"的省略写法 | 用零值代省略 ⇒ 违反 |
| 变更留痕 | 夹具字段变更 MUST 记录理由（口径变化 ≠ 为让测试变绿而改夹具） | 为过测试而改夹具 ⇒ 违反 |

### 2.4 可见行为约束（Visible-Behavior Constraints，FlowCheck 式）

对交互型产物（界面/接口/流水线输出），把意图表达为**用户可见信息流约束**：

| 要素 | 内容 | 示例形态（不含实现） |
|---|---|---|
| 触发 | 什么用户动作 | "提交表单后" |
| 必须可见 | 哪个位置必须出现什么 | "结果区必须出现成功计数" |
| 必须不出现 | 禁止泄漏/禁止出现的表征 | "不得出现内部错误原文" |
| 约束的检视性 | 不读代码也能检视该约束 | 约束以自然语言 + 结构化条目描述 |
| 可确定性 | 约束可被转成确定性检查 | 拒绝模糊项：必须能判定"通过/不通过" |
| **必要要素集**（★v0.10） | 面向人的输出（通知 / 事件 / 报告 / 回执 / 告警）MUST 声明并断言其**必要要素集**（"谁 / 对什么 / 做了什么 / 结果"），MUST NOT 只给**标识符**（编号 / ID）让接收者另行查询 | 示例：一条事件须含「主体 / 目标 / 动作 / 结果」四项；缺项 ⇒ 违反 |
| **要素来源合规**（★v0.10） | 上述要素 MUST 取自**已脱敏**的数据源（MUST NOT 为凑要素而引入明文凭据） | 为补要素而回传敏感原文 ⇒ 违反 |
| **失败要素集：哪一步 + 为什么 + 怎么办**（★v0.31） | 每条**失败 / 拒绝**的面向人输出 MUST 含：**在哪一步失败** / **为什么**（以**实际事实与实际入参**陈述，MUST NOT 只说"失败""不合法"）/ **怎么办**（**可执行**的下一步）；MUST NOT 只给错误码或内部标识（规则号 / 表名 / 字段名）；**"未命中"（正常空结果）MUST 与"失败"区分呈现** | 只给代号 / 空洞处置（如"请联系相关角色"）⇒ 违反 |
| **长内容规模自适应**（★v0.13） | 输出中的**可增长内容**（条目 / 语句 / 日志 / 明细）MUST **摘要优先**（条数 / 体量 / 范围 / 首项），全文以**分页 / 折叠 / 下载**按需获取；MUST NOT 无界渲染或逐条铺开 | 把数十 KB 文本直接摊进界面（不可读、不可检视）⇒ 违反 |
| **截断来源必标注**（★v0.13） | 内容取自**有存储上限**的载体（截断日志 / 采样 / 摘要 / 缓存）时，MUST 标注**可能截断**并给出**完整内容的可核对入口**（原始来源 / 归档 / 下载） | 把截断样本当全文 ⇒ 违反（读者据此做出错误判断） |
| **命中 MUST 可定位到具体对象**（★v0.36） | 判据 / 校验 / 检索的**命中信息**（拒绝理由 / 校验失败项 / 命中规则）MUST 给出**具体对象**（行 / 列 / 字段 / 记录 / 条目）**及其位置**，MUST NOT 只报"整体不合规"；**豁免项 MUST 显式说明"已豁免"**（MUST NOT 让使用者把 A 的问题归因到 B） | 只报"这条语句不合规" ⇒ 使用者只能按界面标记去改**首行**（而真正违规的是另外的对象）⇒ 违反 |
| **命中定位的口径 MUST 与使用者视角一致**（★v0.62） | 位置 / 坐标 MUST 用**使用者实际面对的那份文本**的坐标系；一次动作作用于**多段内容**（多语句 / 多段脚本 / 多文件）时 MUST 同时给出**段序号**与**整体位置**（或直接给整体坐标），MUST NOT 只给"段内相对行号"；任何**剥离 / 折叠文本**的动作（注释过滤、包装、截断）MUST **保行结构**；坐标 MUST 由**产生处成型**（MUST NOT 让展示层从人读文案里反解） | 多段文本里第 2 段的错误报"第 1 行"（使用者去第 1 行找，指向**别的段**）⇒ 比"没有行号"更坏：**引导误判**；剥离动作吞行 ⇒ 其后所有行号失真（且**静默**） |

> ★v0.10 补（真实缺陷回溯）：**面向人的输出是"接口"** —— 它必须自带**决策所需的全部信息**。
> 反例（去业务化）：通知正文只给"单据编号 + 动作名"，接收者无法判断"给谁、对什么、给了什么"，
> 只能回平台二次查询（信息在**输出侧**丢失，而数据在**载荷里本可取**）。
> 与 §2.4 的关系：本节把"必须可见"从**交互界面**推广到**一切面向人的输出载体**。

> ★v0.13 补（真实缺陷回溯）：**"必须可见"还必须"可见得下"** —— 面向人的输出涉及**可增长内容**时，
> 一次摊开会让关键信息被淹没（等于不可见）。故 MUST **摘要优先**（条数 / 体量 / 范围 / 首项），
> 全文走**分页 / 折叠 / 下载**；且当内容取自**有存储上限**的载体时 MUST 标注**可能截断**并给出
> **完整内容的可核对入口**（原始来源 / 归档 / 下载）。
> 反例（去业务化）：① 详情页一次性内嵌数十 KB 文本 ⇒ 界面不可读、检视无从下手；
> ② 只显示附件文件名（内容看不到）⇒ "存了等于没存"；③ 把**被截断的审计留痕**当作全文展示 ⇒ 读者据此误判。
> 判定要点：**规模是约束的一部分** —— 摘要口径与全文口径 MUST 都有落点，且**来源与完整性** MUST 标注。
> ★v0.36 补（真实缺陷回溯，两轮）：**"哪一项不合规"不可省略** —— ① 某校验只报"整条语句不合规"、不说**是哪一项**，界面把标记落在**首行**，而真正违规的是另外两项 ⇒ 使用者把**无关项**当成"被要求方"，据此提出了**与事实相反的诉求**（以为规则要求 A，其实规则管的是 B）；② 第一步修好"可定位"后，按 §4.8 ③ 做**同形态全仓自查**，发现**同一族规则**（主键类）同样是"只说结论、不说对象" ⇒ 一并补齐。判定要点：**可定位性是判据的一部分** —— 命中信息 MUST 能让人**直接找到并处置**那个对象；位置信息 MUST 取自**结构化解析结果**（而非对文本的二次猜测），且**拿不到位置时只给对象名、MUST NOT 编造位置**。

> ★v0.62 补（真实缺陷回溯，两条同源）：**"可定位"还有两个前提** ——
> ① **坐标系必须与使用者一致**：同一批多段内容的报告里，若只给"段内相对行号"，使用者会按**整体行号**去找
> ⇒ 指到**别的段**（比不给位置更坏：**引导误判**）；剥离 / 折叠文本的动作（注释过滤、包装、截断）若吞掉行结构，
> 其后一切行号**静默失真**。② **诊断面与判定面的遍历口径必须显式分离**：本塔既要求"不漏报"又要求"护栏从严"，
> 当两者作用于同一批输入时，若没有明文规定"哪一面全量、哪一面短路"，实现必然在其中一面出错 ——
> 真实反例：为"给全清单"让判定面也继续（把未知错误带进生产），或为"从严"让诊断面在首错停下（清单不全）。
> 判定要点：**诊断面全量（逐条条目，含"通过"项）／判定面 fail-closed（首错即拒），且两面共用同一份事实、MUST NOT 互相污染**。

> 价值：静默行为失败（界面看着正常、数据没落地）正是 F3 的高发形态；
> **能写出来的约束才可能被检查**。

| **判定结果 MUST 自带可陈述原因**（★v0.91） | 判定 / 校验 / 检索类函数 MUST 同时产出**结论与原因**（原因 MUST 可**逐字陈述**：哪一层 / 哪个对象 / 哪个取值 / 与何值冲突），MUST NOT 只回**布尔**让调用方自行解释；调用方与展示方 MUST NOT 以通用文案（「失败」/「不合规」/「成功」）**覆盖或吞掉**判定面给出的原因；确实拿不到原因时 MUST 按「不可判定」呈现（见 §2.2d ★v0.57），MUST NOT 编造 | 判定面只回布尔 ⇒ 违反：原因在**判定面**即丢失，上层只能兜底文案或让使用者自行猜测失败落在哪一层、哪个对象（与 ★v0.31 / ★v0.36 配套：彼管**面向人输出**的要素集与命中定位，本行管**判定面自身**的原因载体） |

> ★v0.91 补（真实缺陷回溯）：**「为什么」必须在判定面就存在** —— ★v0.31 要求面向人的输出携带「为什么」，
> 但若**判定面**只返回布尔（成功 / 失败），上层拿到的结论**没有原因可填**：要么编一个，要么用通用文案覆盖，
> 于是「为什么」在链条的第一环就断了，后面每一环都在转述同一个空洞结论。
> 反例（去业务化）：某推送结果的判定只回「是否成功」的布尔，界面只能显示「失败」，
> 而真正的失败是**外层信封**的错误码 —— 排查从界面完全无法开始，只能回到源码逐层比对；
> 其同一族形态还有：校验只给「不合规」，使用者改了**无关的对象**（与 ★v0.36 同源，区别在于那里缺的是**位置**、这里缺的是**原因**）。
> 判定要点：**结论与原因 MUST 由同一处产生并一起传递**，原因 MUST NOT 由展示层从人读文案里反解（同 ★v0.62 坐标纪律）。

### 2.4a 解析层先于生成层（★v0.80 · P18 `arXiv:2510.17842`）

> 来源：范式参考架构（意图解析器 → 语义嵌入 → 生成器 → 反馈环）与六类风险（alignment / **reproducibility** / bias / explainability / maintainability / security）。
> 为什么并入本节（C5 合并优先）：既有的"契约优先"只说了**要有契约**，没说**契约在哪一步产生** ⇒ 本小节补上"解析层"的位置定义。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| **解析层先于生成层** | 高层意图 MAY 用自然语言表达，但进入实现前 MUST 先落成**结构化契约**（可校验字段 + 校验点位置 + 可复现口径）；**MUST NOT** 由意图直接生成产物 | 意图直达生成 ⇒ 违反（静默规格漂移的结构性来源） |
| **契约可复现** | 同一契约 MUST 能由同一输入重建出同一结果（同源重建 ⇒ 同指纹，见 §2.2b） | 不可复现 ⇒ 视为"完成未定义" |
| **契约可解释** | 契约 MUST 能回答"这条约束从哪来、由谁确认、何时生效" | 来源不明 ⇒ 违反（不可审计） |

### 2.5 双向追溯（Bidirectional Traceability）

```
意图 ─▶ 规格节点 ─▶ 契约槽位 ─▶ 断言 ─▶ 证据
  ◀───────  ◀─────────  ◀───────  ◀─────
```

- 正向：任何交付项 MUST 能回答"它满足哪条契约"。
- 反向：任何断言 MUST 能回答"它守的是哪条契约槽位"。
- 断链即缺陷：**孤儿断言**（无契约）与**裸契约**（无断言）都必须在 Phase 2 退出前清零。

> ★v0.88 补（工件依赖链 MUST 显式，反向演进并入本节 —— C5 合并优先）：追溯链不仅要有**锚**（上图），还必须有**序** ——
> 下游工件（如任务清单 / 实现 / 验收报告）MUST 声明其依赖的上游工件（提案 → 规格 → 设计 → 任务），上游未就绪（不存在 / 未冻结 / 未确认）
> MUST NOT 跳过直接产出下游。机械判定：下游工件存在时，其引用的上游工件 MUST 存在且可解析（引用完整性 = 依赖顺序卡口）；
> 跳过中间工件 ⇒ 该下游**没有验收基准**（孤儿产物）。

## 6. 反模式

| 反模式 | 现象 | 纠正 |
|---|---|---|
| 契约注水 | 契约写得像宣传语，无法判定 | 回炉重写为可机械比对的口径 |
| 断言倒挂 | 先写实现，再补"能通过"的断言 | 断言独立重写，走 RED 流程 |
| 静默降级 | 遇阻就把需求缩水，不报告 | 停下报告，走人工决策点 |
| 追溯断链 | 有断言但说不清守哪条契约 | 补齐契约槽位或删除该断言 |
| 输入域漏斗（★v0.2） | 契约写"接受表名"，实现只认一种写法 | 穷举形态 + 列出拒绝形态 |
| 口径各自解释（★v0.2） | 同一事实在两处得出不同的长度/计数 | 声明唯一口径，多处引用同一处声明 |
| 无解规则（★v0.2） | 规则要求平台不可能满足的属性 | 可满足性检查 + 显式豁免并记录理由 |
| 静默跳过（★v0.2） | 枚举缺项直接跳过该数据，规则静默失效 | 未识别即有信号（告警/报错） |
| 三值压缩（★v0.6） | 把"未命中"当"失败"（或以"错误为空"反推存在）⇒ 分支恒真/恒假 | 三值明确 + 存在性判据单真源 |
| 假成功（★v0.6） | 一侧判成功、另一侧判失败 ⇒ 已完成的操作被重复执行 | 两侧逐字一致的成功标记，且优先于通用失败判定 |
| 只看退出码（★v0.8） | 调用返回成功即宣告生效，目标侧实际未变 | 执行后从目标侧读回核验 |
| 固化环境假设（★v0.8） | 把身份/主机/域写死为常量或用文案固化 ⇒ 与真实环境不符时**静默失效** | 执行时查询事实，命中处收敛 |
| 弱判据开工（★v0.7） | 指令是"让它能跑"，只能靠反复澄清推进 | 按 §2.1a 改写为可验证目标 |
| 半套回落（★v0.9） | 回落时只换一半（旧前缀配新后缀，或新单位配旧精度）⇒ 输出不自洽，而两侧校验各自只看自己那半、**都判通过** | 回落 MUST 成套；无法成套 ⇒ 拒绝产出并显式报错（禁止拼接混合形态） |
| 要素缺失（★v0.10） | 面向人的输出只给编号/ID，接收者必须回平台二次查询才知道"给谁、对什么、给了什么" | 输出侧声明**必要要素集**并断言齐备（要素取自脱敏源） |
| 加工藏分支（★v0.12） | 对全分支成立的加工写在**某一条分支之内** ⇒ 其余分支该字段静默为空，下游兜底显示成"未知/空"，而另一条渲染路径（列表 / 台账）正确 | 加工收敛到**分派之前**的**唯一施加点**（新增分支天然继承） |
| 无界铺开（★v0.13） | 可增长内容一次性全部渲染（数十 KB 文本 / 上千条明细）⇒ 关键信息被淹没，等于不可见 | 摘要优先 + 分页/折叠/下载 |
| 截断当全文（★v0.13） | 展示**有存储上限**载体（截断日志 / 采样 / 摘要）的内容却不标注截断、也不给完整内容入口 | 标注"可能截断" + 给出原始来源/归档/下载入口 |
| 失败提示失能（★v0.31） | 失败只给错误码 / 内部代号，或处置写成"请联系管理员" ⇒ 接收者无法据此决定下一步，只能回查或猜测 | 按失败要素集补齐：**哪一步 + 为什么（用实际事实与实际入参）+ 怎么办（可执行）**；"未命中"与"失败"分开呈现 |
