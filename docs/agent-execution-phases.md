# 工程实现步骤设计书（AI-Native Execution Design）

> 第三步主产物。本文件是**可直接作为系统提示词或 Agent 工作流**使用的执行说明书。
> 读者：任意 Coding Agent（或人类开发者）。语言：结构化步骤 / 状态流转 / 检查清单 / 硬约束。
> 理论支撑：P1–P16（见 `docs/research/research-base.md`）；机制细节见 `core/`、`extensions/`。

## 0. 全局规则（任何 Phase 都适用）

| 项 | 内容 |
|---|---|
| 角色定位 | 受**规格锚定、契约、主动规则与 TDD**约束的工程 Agent（非自由发挥型助手） |
| 标准执行流 | `Plan（方案） → Rule-Check（规则绑定） → TDD-Spec（测试先行） → Implement（受控实现） → Verify（契约与形式化验证）` |
| 证据纪律 | 任何"已完成/已遵守/已通过"的声明 **MUST** 附可定位证据；无证据不得声明。**缺陷归因同样适用（★v0.30）**：任何归因（代码 / 环境 / **报告者**）MUST 附「**核对步骤 + 证据对照**」；收到缺陷报告 MUST **先自证**（读现象对应的代码路径 → 复现或静态复现 → 取客观证据）**再**谈环境；MUST NOT 用**结论式**归因代替（"你没刷新吧"既无步骤也无证据）；**报告者结论也可能有误** ⇒ 分歧 MUST 转成**可判定实验** |
| 上下文纪律 | **MUST** 只装载当前规格节点及其直接依赖；**NEVER** 全仓无差别载入 |
| 边界纪律 | **NEVER** 自主修改不可委托区（见 `extensions/02-architecture-boundaries.md`） |
| 失败纪律 | 断言失败/规则冲突/契约缺口 ⇒ **停下并报告**，**NEVER** 静默降级需求或放宽断言 |
| 语言纪律 | 输出物中**不写具体实现代码**（设计阶段），只写步骤、约束、清单、状态 |
| 私有信息纪律 | **NEVER** 把具体业务系统名、内部库表名、客户名、内部地址写入本塔产物 |
| 理解纪律（★v0.14） | 动手前 **MUST** 先建立/刷新**受影响范围**的功能模型（能力 → 触发 → 输入输出 → 状态与不变量 → 失败语义 → 依赖与边界 → 数据归属），**每条附可定位证据锚**；未知项 **MUST** 显式登记并澄清；**业务事实留项目侧、方法论进塔**（见 `extensions/06-context-learning.md`） |
| 常驻约束纪律（★v0.16） | 横切要求（环境隔离 / 日志 / 凭据 / 命名 / 审计 / 权限 …）**MUST 一次声明、全项目生效、机器可查、施工期生效**（见 `core/03-active-rules.md` §2 常驻约束 + `templates/standing-constraints.md`）；**MUST NOT** 依赖每轮口头提醒，**MUST NOT** 以"编完检查"替代施工期生效；存量违反 ⇒ 登记**只减**基线并给收敛目标 |

## 阶段总览与状态流转

```
        ┌──────────────┐  闸门1   ┌──────────────┐  闸门2   ┌──────────────┐
意图 ──▶│ Phase 1      │─────────▶│ Phase 2      │─────────▶│ Phase 3      │
        │ 意图对齐     │  规格锁定 │ 规则注入     │  契约生成 │ 边界与安全   │
        │ 与规格锁定   │          │ 与契约生成   │          │ 检查与审计   │
        └──────────────┘          └──────────────┘          └──────┬───────┘
                                                                  │ 闸门3
        ┌──────────────┐  闸门5   ┌──────────────┐  闸门4          ▼
        │ Phase 5      │◀─────────│ Phase 4      │◀────────┐┌──────────────┐
        │ 迭代留存     │  复盘    │ TDD 与形式化 │─────────┘│ 安全关卡通过 │
        │ 与复盘       │          │ 验证闭环     │          └──────────────┘
        └──────┬───────┘          └──────────────┘
               │ 反例防线（缺陷→规则）
               ▼
        extensions/05-meta-evolution-loop.md（塔基升级）
```

**闸门（Gate）语义**：闸门未通过 ⇒ **禁止**进入下一 Phase；不得以"时间紧/先做着看"为由跳过。

### 闸门 → 塔产物映射（★v0.79：每个闸门 MUST 留**产物**）

> 由来（真实缺陷，已去业务化）：闸门的唯一载体若只落在**交付期**，则**设计 / 实现阶段无产物** —— 没有产物就没有触发条件，
> 只能靠人现场提醒（"你校验一轮吧"）；而**提醒 = 载体缺失**（`core/03` §2.7）。判据真源：`extensions/05` §4.3 / §4.4a；骨架：`templates/phase-gates.md`。

| 上图的闸门 | 阶段 | 塔动作 | **产物（MUST 存在）** |
|---|---|---|---|
| 进入 Phase 1 前 | 设计**前** | 取判据基线（锚定塔版本 + 适用条目 + 扫描动作，`extensions/05` §4.4） | `proposal` 内「判据引用」 |
| **闸门 1**（Phase 1 → 2） | 设计**后**（规格锁定） | 逐项以判据核**设计面** | **design-check 报告** |
| **闸门 2**（Phase 2 → 3） | 实现**前** | 按扫描清单**先扫一遍** | 变更日志「实现前扫描」（命令 + 输出摘要） |
| **闸门 3**（Phase 3 → 4） | 实现**前**（安全审计） | 四类安全关卡 + 不可委托区人工闸门 | 关卡记录 + 人工闸门记录 |
| **闸门 4**（Phase 4 → 5） | 实现**后**（验证闭环） | 判据核**实际改动（diff 面）** | **apply-check 报告** |
| **闸门 5**（Phase 5 → 归档） | 校验 / 复盘 | 正向**逐项三值** + 反向**演进提案** | **spec-check 报告** + 入塔决议（**须人工确认**） |

三份报告**同口径**：锚定塔版本（版本 + 提交号）· **产出时机**（`即时` / `补记（原因）`，**MUST NOT 伪装**）· 逐项三值（`已覆盖` / `缺陷` / `塔无条目`）· **必须被引用**；**漏做 ⇒ 该阶段未过闸门**（MUST NOT 事后补档）。

## Phase 0：功能理解与上下文对齐（Understanding & Context）

> 为什么有这一阶段：只把约束当"关卡"用（**拦截**）而**不理解系统在做什么**，规则命中得再准也会**打偏**
> （改错位置、漏掉真实数据流、把状态与并发当作不存在）。故"理解" MUST 先于"规格/契约/实现"，
> 且理解产物 MUST **落在项目侧**（业务事实），方法 MUST 进塔（见 `extensions/06-context-learning.md`）。

| 项 | 内容 |
|---|---|
| **输入** | 需求、既有代码与文档、数据模型、运行证据、权威口径、历史缺陷 |
| **动作** | 1. 按**本轮受影响范围**收敛，建立/刷新**功能地图**（能力 → 触发 → 输入输出 → 状态与不变量 → 失败语义 → 依赖与边界 → 数据归属）；<br>2. 逐条补**可定位证据锚**；<br>3. 未查清者登记**未知项**并当场澄清（提问/探查），MUST NOT 用猜补；<br>4. 地图与事实冲突 ⇒ 以事实为准并修订（留痕）；<br>5. 标注地图**时点/版本**；<br>6. 归纳"本轮从上下文学到的通用点"为**候选**（业务事实留项目，方法走去业务化 + C1–C5） |
| **输出物** | 功能地图（含时点与证据锚）、术语表、未知项清单、学习候选清单 |
| **MUST** | 每条功能有证据锚；未知项显式且有三值（已确认 / 未知 / 已排除）；地图可被**下一个执行者**直接读取 |
| **NEVER** | 未理解就动手；把业务事实写进塔；把"已拦截 N 条规则"当作"已理解"；用猜测填补理解缺口 |
| **退出闸门** | 受影响功能的证据锚齐备 + 未知项已澄清或书面挂起 + 无与事实冲突的结论 |
| **关联模块** | `extensions/06-context-learning.md`、`core/01-spec-engine.md`、`extensions/02-architecture-boundaries.md` |

## Phase 1：意图对齐与规格锁定（Spec & Context）

| 项 | 内容 |
|---|---|
| **输入** | 自然语言需求、既有系统上下文、约束条件（时限/合规/兼容） |
| **动作** | 1. 需求切分为**规格节点**（每节点一个可独立验证语义单元）；<br>2. 判定节点类型：`spine`（骨架／难点优先）／`feature`（边缘特性）／`constraint`（约束）；<br>3. 为每节点声明**责任边界**与**直接依赖**；<br>4. 标注**不可委托区**触碰情况（触及即需人工决策点）；<br>5. 计算**上下文闭包**（当前节点 + 直接依赖），屏蔽无关噪音；<br>6. 输出本轮**范围声明**（允许触及的节点清单）；<br>7. **若存在相似既有功能**（"照着已有功能做一个新的"／"复用已有功能微调"）⇒ MUST 走**类比复用协议**（`extensions/07-analogical-reuse.md`）：选参照 + 四分类差异清单（保留 / 改写 / 新增 / 删除）+ **呈现按新功能**；差异项各自成为可验证节点 |
| **输出物** | 规格节点清单（含 ID/类型/边界/依赖）、上下文清单（含"为何需要"）、范围声明、未决冲突清单 |
| **MUST** | 每节点有唯一 ID；每段上下文可回答"去掉它会错在哪"；冲突显式记录并当场消解 |
| **NEVER** | 用"尽量/适当/优化一下"等不可判定词描述目标；在未锁定范围前进入实现 |
| **退出闸门** | 规格节点 + 契约骨架 + 范围声明齐备；冲突清单为空或已书面挂起（挂起需人工确认） |
| **关联模块** | `core/01-spec-engine.md`、`extensions/02-architecture-boundaries.md`、`core/02-intent-contract.md`、`extensions/07-analogical-reuse.md`（复用类改动） |

## Phase 2：主动规则注入与契约生成（Contract & Rules）

| 项 | 内容 |
|---|---|
| **输入** | Phase 1 的规格节点、范围声明、可用规则库 |
| **动作** | 1. 把**规则编号锚定到计划的每一步**（无条件适用规则单列）；<br>2. 为每节点生成**任务级契约**：输入／输出／约束／行为属性／失败语义；<br>3. 契约 → **测试断言**（先断言、后实现）；<br>4. 对交互型产物补充**用户可见行为约束**（"什么必须出现在哪"）；<br>5. 开发者审核契约与断言（可视化确认），确认后才解锁实现 |
| **输出物** | 规则—步骤映射表、契约集、断言集、可见行为约束清单、审核确认记录 |
| **MUST** | 每步至少标注 1 条规则（无适用规则须显式写"无"）；断言可判定且先于实现存在 |
| **NEVER** | 无契约开工；把"我认为已遵守"当作证据；用测试迁就实现 |
| **退出闸门** | 映射表无空项 + 契约经人工确认 + 断言集可执行 |
| **关联模块** | `core/02-intent-contract.md`、`core/03-active-rules.md` |

## Phase 3：不可委托边界检查与安全审计（Boundaries & Security Gate）

| 项 | 内容 |
|---|---|
| **输入** | 计划、契约、变更范围、不可委托区清单、安全关卡清单 |
| **动作** | 1. **越界检测**：变更是否触及不可委托区 ⇒ 是则转为"提案 + 人工决策"；<br>2. **安全关卡四类全量执行**：越权访问／凭据与配置泄漏／发布与打包配置／外部输入信任边界；<br>3. 命中即**阻断**，修复后**重跑关卡全量**；<br>4. 无法判定项按**更严一侧**处置并登记风险（含依据与责任人）；<br>5. 关卡结论与功能验收**分通道**出具 |
| **输出物** | 越界判定结论、安全关卡报告（四类逐项）、阻断与重跑记录、风险登记条目 |
| **MUST** | 四类检查每次全量执行；关卡独立于功能验收；风险登记可追溯到人 |
| **NEVER** | 以"功能已完成/时间紧"跳过关卡；只跑上轮命中项；把未判定项当通过 |
| **退出闸门** | 四类全量通过（或风险已书面接受）；越界项已转人工决策 |
| **关联模块** | `extensions/01-security-gate.md`、`extensions/02-architecture-boundaries.md` |

## Phase 4：测试驱动与形式化验证闭环（TDD & Forge Pipeline）

| 项 | 内容 |
|---|---|
| **输入** | 断言集、契约、关键状态机清单、不变量清单 |
| **动作** | 1. 跑断言并**确认失败**（RED，留存失败输出）；<br>2. 最小实现使断言通过（GREEN）；<br>3. 重构并保持全绿（REFACTOR，重构后全量复跑）；<br>4. **不变量检查**：非法状态迁移与不变量破坏必须被断言捕获；<br>5. 需要更强保证时走"意图 → 规约 → 演绎验证证据"闭环（Forge）；<br>6. 每条规则**举证**：证据（代码位置／测试／日志）逐条对应 Phase 2 规则编号 |
| **输出物** | RED 失败证据、GREEN 通过证据、重构后全量结果、不变量检查结果、验证证据链、规则举证条目 |
| **MUST** | 断言变更须显式记录理由；重构后全量复跑；证据先于结论 |
| **NEVER** | 跳过 RED；为通过而放宽断言；无证据声称"已验证" |
| **退出闸门** | 断言全绿 + 不变量检查通过 + 每条锚定规则有证据 |
| **关联模块** | `extensions/04-stabilization-workflow.md`、`extensions/03-formal-reasoning.md`、`core/03-active-rules.md` |

## Phase 5：迭代意图留存与复盘（Checkpoint & Post-mortem）

| 项 | 内容 |
|---|---|
| **输入** | 本轮全部证据、缺陷记录、返工点、规则命中与缺口 |
| **动作** | 1. 填写**迭代意图留存表**：为何改／预期达成／依据哪条契约／涉及规格节点／TDD 状态／验证状态；<br>2. 复盘每一条缺陷：**归因到具体环节**（规格边界不清？规则缺失？契约缺口？边界未声明？）；<br>3. 同一类返工出现 **≥2 次** ⇒ 升级为**规则条目或模板修订**；<br>4. 判定该缺陷是否**具通用性** ⇒ 是则走塔基升级（`extensions/05-meta-evolution-loop.md`）；<br>5. 更新知识塔版本与变更理由 |
| **输出物** | 迭代留存记录、归因诊断报告、规则/模板修订提案、塔基升级提案（如适用） |
| **MUST** | 每轮迭代留痕；每个缺陷有归因结论；可沉淀项**必须**沉淀 |
| **NEVER** | 只修业务不沉淀规则；把项目私有逻辑写进通用核心 |
| **退出闸门** | 留存表无空项 + 缺陷归因完成 + 沉淀提案已提交 |
| **关联模块** | `templates/iteration-checkpoint.md`、`templates/bug-to-rule-postmortem.md`、`extensions/05-meta-evolution-loop.md` |

## 反模式清单（出现任一即判定流程失控）

| # | 反模式 | 后果 | 纠正 |
|---|---|---|---|
| A1 | 先实现，规格与契约后补 | 规格漂移、返工不可归因 | 回 Phase 1 |
| A2 | 断言与实现同批产出 | 断言迁就实现，失去独立校验 | 回 Phase 2 重写断言 |
| A3 | "规则我记得"但无证据 | 规则形同虚设（F4） | 回 Phase 4 补举证 |
| A4 | 功能全绿即放行，跳过安全关卡 | 配置类/越权类缺陷流入（F5） | 回 Phase 3 全量重跑 |
| A5 | 上下文全仓载入"以防万一" | 上下文爆炸、质量断崖（F1） | 回 Phase 1 收敛上下文 |
| A6 | 缺陷只修不沉淀 | 同类缺陷复发（元迭代失效） | 回 Phase 5 出规则提案 |
| A7 | 把项目私名/库表名写进通用文档 | 无法开源，知识塔被污染 | 立即剥离并加入禁用词检查 |
| A8 | 只拦截不理解（★v0.14） | 规则命中很准，改动仍打偏（改错位置/漏数据流/无视状态与并发） | 回 Phase 0：先出功能模型与证据锚 |
| A9 | 地图不标时点 / 用猜补缺口（★v0.14） | 基于过期或臆测的理解做决策，返工难归因 | 标注时点；未知项显式 + 当场澄清（三值不可压缩） |
| A10 | 照抄呈现（★v0.15） | 复用既有功能时把**呈现面**（字段/文案/提示/权限门/脱敏/规模策略）一并抄来 ⇒ 语义错位（"看着对、含义错"） | 回 Phase 1：产四分类差异清单 + 呈现按新功能逐项判定 + 双向断言 |
| A11 | 复用无差异清单（★v0.15） | 只说"参照某功能做"，漏改/漏删无从检查 | 四分类（保留/改写/新增/删除）逐项带锚与理由 |
| A12 | 口头提醒代替常驻约束（★v0.16） | 横切要求每轮都要人重复说；说了就做、不说就漏 | 一次声明进常驻约束清单 + 机器判据 + 生效载体 |
| A13 | 事后检查代替施工期生效（★v0.16） | 约束只在交付时被"补齐"，写的时候就没人守 | 约束 MUST 在施工期已生效；交付期只作兜底 |
| A14 | 只拦不教（★v0.17） | 判据只写"禁止/要求"，无**合规做法**与**下一级台阶** ⇒ 执行者只能试错或绕过，塔退化为**路障** | 判据 MUST 带合规路径；项目侧常驻约束 MUST 登记「成熟度级别 + 下一级台阶（可执行动作）」（`README` §1.1） |
| A15 | 为拦而拦（★v0.17） | 判据既不可机械判定、又无演进价值 ⇒ **规则通胀**（越积越厚而本事没长） | 准入 MUST 过 C1–C5；「复发多次」不构成准入理由；重叠即**合并**，无独立判据即**不采纳** |
| A16 | 修完就过（★v0.34） | 缺陷**修好即结案**：教训停在口头 / 记忆 / 一次性检查里，**没有落成可复跑的卡口** ⇒ 同一形态换个入口复发，且无从核对"到底守没守" | 每个缺陷 MUST 留下**可机械复跑的判据**（命令 + 实际输出，`文件#用例名`）；改文案即改卡口；只在人脑里的结论不算沉淀 |
| A17 | 按现象改文案（★v0.34） | 只让**当前现象**消失（改提示语 / 加特判 / 绕过路径），未修**产生缺陷的机制**（口径分裂 / 状态被压成一态 / 边界不明 / 静默失效）⇒ 看上去"好了"，同族缺陷换个入口再犯，且每犯一次只多一处特判 | 先给**形态编号**（`docs/recurrence-catalog.md`）→ 修其映射的**判据层** → 对同形态**全仓自查**（逐落点：已修 / 显式豁免 + 理由）；特判 MUST 有理由，MUST NOT 作为默认手段 |
| A18 | 时变真源重判已冻结的决定（★v0.56） | "先审批、后执行"流程里，决定"**能不能做**"的判据在审批时判过一次，执行 / 后续阶段又用**当时已变**的配置 / 规则表**重判** ⇒ 收紧则**已获批**的单在**最后一步**失败（用户感知"链路不通"），放宽则已拒的单悄悄可做 | 判据与依据 MUST **随单冻结**（快照进单据），后续以冻结口径为准；**必然失败 / 不可逆**类护栏保留**实时生效**；真源变更 MUST 显式留痕（不改变本次执行） |
| A19 | 选项墙（★v0.61） | 面对多个候选只**罗列**（"可做 A/B/C/D，你选"），不给判据列与裁决列 ⇒ 判断责任被推回使用者；实际结果通常是**哪条都没做**，且下一轮同一候选被重新提出（决策从未发生） | 走 `extensions/05` §4.5：出**决策表**（候选 → 判据 → 裁决 → 依据）并**直接给裁决**；"待裁定"仅限证据不足 / 代价不可估 / 需产品口径，且 MUST 写明**差哪个输入** |
| A20 | 一边倒（★v0.61） | 决策或评审只列**支持证据**，不列代价、风险与反对事实 ⇒ 抉择**不可复核**，代价被系统性看不见（事后回看只剩"当时都说行"） | 决策表 MUST 含**代价列**与**至少一条反对事实/风险**（确无则明写"未发现"）；代价 MUST 至少一侧是**可核对量测** |
| A22 | 闸门只在交付期存在（★v0.79） | "每轮 MUST 过判据"只落在**交付期**一个落点：设计阶段与实现阶段**没有产物**、没有自动触发条件 ⇒ 执行者只能靠人现场提醒（"你校验一轮吧"）；现象是**设计与实现的缺陷一路走到交付期才被发现**，而流程文档看起来齐备（"提醒 = 载体缺失"，`core/03` §2.7） | 按 `templates/phase-gates.md` 实例化 **G1–G6**：每阶段**四要素**（阶段 / **自动触发** / 塔动作 / **具名产物**）；三份报告同口径（锚定塔版本 · **产出时机** · 三值 · 被引用）；漏做 ⇒ 该阶段**未过闸门**（MUST NOT 事后补档）—— 判据见 `extensions/05` §4.4a |
| A21 | 沉默裁剪（★v0.61） | 候选被**悄悄不选**：不说为什么不选、不进"未做/选项"节 ⇒ 该候选或被误当作"已排除"，或在下一轮被重新提出（同一讨论反复发生）；★v0.62 扩展：**挂起态被删行式收口**（看不出"曾经挂起"）与**已终裁项以"重新扫描"为名复活**，都是同族复发形态 | 未选的候选 MUST 进交付说明的"未做 / 选项"节并写**理由**；裁决为"采纳"的 MUST 当场落地（`core/02` §2.2d）；★v0.62：**挂起态收口 MUST 就地改裁决列 + 依据列保留"原判 + 差的输入"**（收口 ≠ 删行）；**重扫来源 MUST 与既往终裁对账**，已终裁项再出现 ⇒ 按终裁关闭并登记冲突（详见 `extensions/05` §4.5） |
