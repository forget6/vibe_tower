# 任务场景识别与分流（Task Mode Routing）

> ★v0.86 新增。解决的问题：**流程成本恒定化** —— 无论任务性质，一律套同一套全流程（三段闭环 + 全量
> 证据包），一次性小任务被流程拖垮，流程本身被讨厌然后被跳过（与「验证成本恒定化」同族，但发生在
> **任务级**而非**轮次级**）。
> 分层依据（承接既有结构，MUST NOT 新造机制）：H0–H3 阶梯（§4.4b）· 协作模型选择（`extensions/04` §2.3）·
> 度量口径（`extensions/04` §2.4a）· 耗时台账（`extensions/05` §4.4c）。

## 2. 识别与声明（MUST 打印，可覆盖）

1. **开工前**：按触发信号自动识别场景，**打印声明**（例：`[mode] scene=bugfix（依据：存在失败复现 + 口径含"修复"）`）；
2. **识别不确定**（信号冲突）⇒ 按**更重**的场景处理（宁可重不可漏），并向用户确认；
3. **用户可覆盖**：用户显式指定场景 ⇒ 以用户为准并留痕；
4. 声明并入既有**模式声明**（项目侧约束同族：场景 + 协作模式 + 判据强度，一行写清）。

## 3. 轻量化的红线（什么不能被"轻量"掉）

无论场景多轻，以下四项**任何场景不可省**：

1. **验证入账**：至少一行耗时台账（§4.4c；脚本场景允许只记 `tier=script` 一行）；
2. **证据留痕**：结论 MUST 可核对（可机械核对判据——证据不是形容词）；
3. **修因不修表**（bugfix 场景）：修复 MUST 落到根因层，症状层补丁 MUST 声明为临时并登记；
4. **不可逆动作守卫**（配置/数据场景）：默认不执行 + 触发面唯一，MUST NOT 因场景轻而省。

> ⚠️ 反模式：「一次性脚本」直接被生产环境引用 = **绕过全部守卫的通道**。一次性脚本要转正 ⇒
> MUST 按目标场景重走该场景的必做项（MUST NOT 就地升级）。

## 4. 与耗时台账的衔接

台账 schema 增加可选 `scene` 字段（自由文本，由调用方声明）；`-Stats` 按 scene 分组可回答
"哪类任务最费时间"——场景维度与层维度（tier）正交，MUST NOT 混用。
