# 阶段闸门骨架（Phase Gates · G1–G6）

> 用途：把"判据**什么时候**用、**产出什么产物**"从"靠执行者记性（或靠人现场提醒）"变成**每阶段有产物**的固定链路。
> 归属：本文件是**模板**（无业务信息）；填好的实例属**项目**，`MUST NOT` 回写进塔。
> 判据真源：`extensions/05-meta-evolution-loop.md` §4.3（正向应用进闸门）· §4.3a（闸门版本无关）· §4.4a（阶段产物闸门）；
> 实例建议落项目侧 `docs/vibe/phase-gates.md`（或并入项目约定文件）。

## 一、六阶段闸门（照此实例化；`<>` 换成本项目的路径与命令）

| 闸门 | 阶段 | 触发（**自动条件，不需人喊**） | 塔动作（判据） | 产物（MUST 存在，路径为本项目值） |
|---|---|---|---|---|
| **G1** | 设计**前** | 需求落 `proposal` **之前** | 取**判据基线**：锚定塔版本 + 本轮适用条目 + 每条的可执行扫描动作（`extensions/05` §4.4） | `proposal` 内「**判据引用**」小节（≥3 条塔条目 + 本项目对应卡口） |
| **G2** | 设计**后**（冻结时） | 设计 / 规格 / 任务**冻结那一刻** | 逐项以判据核**设计面**（高频形态 `H*`、反模式 `A*`、意图契约） | `<…/tower-design-check-v<塔版本>.md>` |
| **G3** | 实现**前** | 写**第一行实现代码之前** | 按项目**扫描清单**先扫一遍（判据 → 扫描动作） | 变更日志的「**实现前扫描**」小节（命令 + 输出摘要） |
| **G4** | 实现**后** | 目标测试转绿**之后** | 以判据核**实际改动（diff 面）** + 缺陷处置四步 | `<…/tower-apply-check-v<塔版本>.md>` |
| **G5** | 校验（verify） | 全量回归通过**之后** | **正向**逐项三值 + **反向**演进提案 | `<…/tower-spec-check-v<塔版本>.md>` |
| **G6** | 归档 | 校验无 Critical | 反向提案入塔（**须人工确认**） | 塔提交号 + 项目绑定同步（版本 / 提交号） |

## 二、产物纪律（G2 / G4 / G5 三份报告**同口径**）

1. MUST 写明 **锚定塔版本**（版本号 + 提交号）与 **产出时机**：`即时`（本阶段当场产出）或 `补记（<原因>）` —— **MUST NOT 伪装即时**；同一根因**重复出现** ⇒ 记为**载体缺陷**（补载体，不补报告）。
2. MUST 含**逐项三值结论**：`已覆盖` / `缺陷` / `塔无条目`（只写"通过"视为**未校验**）。
3. MUST 被**交付文档或变更文档引用**（写完没人读 = 产物孤岛 = 等于没做）。
4. **MUST NOT 事后补档**：漏做 ⇒ 该阶段判定为**未过闸门**（补一份文档**不改变**判定）。

## 三、机械化的两条建议（"不为拦而拦"）

- 闸门 MUST 落在**版本无关**的卡口（`extensions/05` §4.3a）：从**版本真源**解析"当前是谁"，再断言其产物齐备；
- 卡口 SHOULD 断言三件事：① 闸门表存在且**每行四要素**（阶段 / 触发 / 塔动作 / 产物）齐备；② 各阶段产物**真实存在**（文件系统可核对，MUST NOT 只判文档里的一句话）；③ 每份产物含上节契约（锚定版本 / 产出时机 / 三值）**且被引用**；
- **规模自适应**（塔 `README` §4）：单行修复、纯文档格式改动可**跳过**，并在交付说明写明"按规模自适应跳过"的理由；MUST NOT 硬套流程。

## 四、常见退化（出现即流程失控）

| 退化 | 长相 | 纠正 |
|---|---|---|
| **闸门只在交付期存在** | 设计 / 实现阶段**无载体**（无产物、无触发、无卡口）⇒ 只能靠人现场提醒 | 按上表补齐 G1–G4 的**产物**与自动触发条件 |
| **产物在马后** | 先改完再补报告 ⇒ 等价于"只有反向流" | 标 `补记` 并写根因；同根因重复 ⇒ 补载体（闸门 / 清单 / 卡口） |
| **产物孤岛** | 报告写完无人引用、无人读 | 交付文档 MUST 引用各阶段产物 |
| **形式过闸** | 用"文件存在"或"写上通过"代替"内容合规" | 断言**内容契约**（锚定版本 / 产出时机 / 三值结论） |
