# 迭代意图契约留存记录表（Iteration Checkpoint）

> 用途：每轮迭代**必须**填写；这是 `extensions/04-stabilization-workflow.md` 的意图证据落地载体，
> 也是 `extensions/05-meta-evolution-loop.md` 塔基升级的输入。
> 约束：留痕是阻断项——未填写的迭代**不得**标记为完成。

## 一、主表（每轮一行）

| 轮次 | 目标意图摘要 | 规格节点 | 依据契约 | 遵守的主动规则 | TDD 状态 | 规则证据 | 验证状态 | 偏离说明 |
|---|---|---|---|---|---|---|---|---|
| `<vX.Y>` | `<为什么改 + 预期达成>` | `<node-id>` | `<contract-id>` | `<rule-id, ...>` | `RED 已留 / GREEN / REFACTOR 全绿` | `<类型#定位>` | `待验证 / 已通过 / 已阻塞` | `无 / <偏离及理由>` |
| v0.1 | 初始化核心骨架（拉通最小闭环） | `spine-core` | `C-001` | `SEC-01, BND-01` | RED 已留 / GREEN / REFACTOR 全绿 | `test#spine_smoke, log#ci-123` | 已通过 | 无 |

### 字段填写规则（缺一不可）

| 字段 | 合格标准 | 不合格示例 |
|---|---|---|
| 目标意图摘要 | 有"为什么"，不只是"做了什么" | "改了 X 模块" |
| 规格节点 | 引用 `core/01` 的节点 id | "若干模块" |
| 依据契约 | 引用契约 id 或槽位 | "按需求" |
| 遵守的主动规则 | 规则编号列表（无适用则写"无"） | "按惯例" |
| TDD 状态 | RED 证据是否留存 + GREEN + REFACTOR 是否全量复跑 | "已测" |
| 规则证据 | 类型 + 精确定位（测试名/文件行/日志 id） | "已遵守" |
| 验证状态 | 三态之一，且与证据一致 | "应该没问题" |
| 偏离说明 | 任何偏离契约/规则的说明与理由；无则写"无" | 空白 |

## 二、复盘段（每轮结束填写）

| 项 | 内容 |
|---|---|
| 本轮缺陷数 | `<n>`（含测试失败与线上问题） |
| 归因分布 | 规格边界 `<n>` / 规则缺失 `<n>` / 契约缺口 `<n>` / 边界未声明 `<n>` / 上下文缺失 `<n>` / 其他 `<n>` |
| 高频返工项 | `<同类返工 ≥2 次者>`（**MUST** 升级为规则或模板修订） |
| 是否具通用性 | `是 / 否`（是 ⇒ 出塔基升级提案） |
| 沉淀动作 | `<规则提案 id / 模板修订 / 无>` |
| 下轮阻断项 | `<本轮流下的未决项>` |

## 三、与塔基升级的衔接

```
迭代留存（本表） ──▶ 归因诊断（templates/bug-to-rule-postmortem.md）
                              │
                    ┌─────────┴──────────┐
                    ▼                    ▼
       通用性 = 否：项目侧规则/模板        通用性 = 是：塔基升级提案
        （就地生效，下轮适用）        （extensions/05：core/ 或 extensions/ 修订 + 版本号）
```

- **MUST**：每轮留存表由"实现者之外的角色"复核一次（复核人只核"证据是否可定位 + 字段是否齐备"）。
- **NEVER**：用本表记录具体业务私密信息（客户名、内部库表名、凭据）；需要业务细节时引用内部编号。
