# 功能地图模板（Functional Map Template）

> 用途：把"这个系统**到底在做什么**"落成**可核对、可传递、可演进**的项目侧工件，供每轮开工前读取与刷新
> （见 `extensions/06-context-learning.md` §2.1）。**本模板不含业务信息**，可随知识塔一起开源；
> 填写后的实例**属于项目**（含业务事实），MUST NOT 回写进塔。
> 字段填写规则：`MUST` = 不留空（未知也 MUST 写"未知 + 澄清动作"）；`NEVER` = 禁止的填法。

## 0. 头部（MUST 填）

| 字段 | 填写规则 |
|---|---|
| 项目 / 系统 | `MUST` 写项目自称（业务事实，留项目侧） |
| **最后更新时点 / 版本** | **`MUST`** 写日期或版本号 —— 地图是**活工件**，读者必须知道这是"什么时候的理解" |
| 本轮范围 | `MUST` 写当前改动触及的能力（MUST NOT 全量铺开；按需收敛） |
| 未决项数量 | `MUST` 与第 3 节条数一致 |

## 1. 能力条目（每项一个，`MUST` 附证据锚）

> 模板：`能力 → 触发 → 输入/输出 → 状态与不变量 → 失败语义 → 依赖与边界 → 数据归属 → 证据锚`
> **证据锚**：可定位的代码位置 / 接口 / 数据模型 / 既有用例 / 权威口径（**`NEVER` 写"见代码"这类不可定位的话**）。
> **未知项**：任一项没查清 ⇒ 写 `未知（澄清动作）`；**`NEVER`** 用推测值填满。

| # | 能力 | 触发 | 输入 → 输出 | 状态与不变量 | 失败语义 | 依赖与边界 | 数据归属 | 证据锚 |
|---|---|---|---|---|---|---|---|---|
| 1 | | | | | | | | `` `path` `` / `` `path#用例` `` |
| 2 | | | | | | | | |
| … | | | | | | | | |

## 2. 术语表（`MUST` 一处定义）

| 术语 | 系统内定义（唯一口径） | 证据锚 | 同义词/别名（`MUST` 只保留一处正式口径） |
|---|---|---|---|
| | | | |

## 3. 未知项清单（`MUST` 显式，`NEVER` 省略）

| # | 未知点 | 影响（不澄清会错在哪） | 澄清动作 | 负责人/状态 |
|---|---|---|---|---|
| 1 | | | 提问 / 探查（指明查什么） | |

## 4. 与代码事实的一致性核查（`MUST` 留痕）

| 检查项 | 规则 |
|---|---|
| 冲突处理 | 地图与代码/运行事实冲突 ⇒ **以事实为准**，修订地图并写下**修订理由与日期**（`NEVER` 为自洽而保留旧结论） |
| 三值 | 每条功能状态 MUST 为「已确认 / 未知 / 已排除」之一（`NEVER` 把"未查清"写成"已确认"） |
| 证据锚有效性 | 引用路径/用例名 MUST 真实存在（建议由**项目侧机械卡口**校验，防地图腐化） |

## 5. 学习出口（`MUST` 每轮写一次）

| 本轮从上下文学到 | 业务事实（留项目） | 去业务化后的通用形态 | 反例 | 去向（项目侧就地生效 / 过 C1–C5 后升塔候选） |
|---|---|---|---|---|
| | | | | |

> `NEVER` 只拦截、不学习（只写"已按规则拦截"而无学习出口 ⇒ 视为本轮未完成）。
