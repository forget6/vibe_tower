# 02. 架构边界与不可委托区（Context Before Code）

> 理论支撑：P7（Context Before Code: An Experience Report）
> 对抗失效：**F6 架构侵蚀**
> 落地阶段：Phase 1（边界声明）、Phase 3（越界检测）

## 1. 目标

显式锚定**核心架构红线**，防止 Agent 为了"快速实现功能"而破坏全局架构。
核心口径：**架构上下文先于代码**——动手前先对齐"这次改在架构的哪个位置、影响哪些契约"。

## 2. 核心机制

### 2.1 不可委托区（Non-Delegation Zones）

**不可委托区** = Agent **不得自主修改**、只能提案并由人类决策的区域。

| 类别 | 典型范围 | 为什么不可委托 |
|---|---|---|
| 核心架构骨架 | 分层边界、模块依赖方向、扩展点契约 | 一旦破坏，全局维护成本陡增且难以局部回退 |
| 对外契约 | 对外接口/数据格式/兼容性承诺 | 影响外部使用者，破坏即不可逆 |
| 安全边界 | 鉴权与授权判定点、密钥管理、信任边界 | 反转即产生越权与泄漏风险 |
| 数据模型红线 | 数据一致性约束、迁移与回滚路径 | 错误变更可能导致数据不可恢复 |
| 发布与部署 | 产物形态、发布通道、回滚机制 | 影响线上可用性与可回退性 |

### 2.2 边界声明格式（逐项写清）

| 字段 | 含义 | 硬性约束 |
|---|---|---|
| `zone_id` | 稳定编号 | MUST 唯一 |
| `scope` | 边界范围（含**排除项**：哪些看着像但不属于） | MUST 写明否定边界 |
| `rationale` | 为什么不可委托 | MUST 具体到风险，不写"很重要" |
| `exception_path` | 允许的例外流程（谁批、留什么证据） | MUST 非空（否则等于"永远不改"，会失效） |
| `detection` | 如何检测被触碰（依赖变更/契约变更/文件范围） | MUST 可判定 |
| `owner` | 责任角色 | MUST 非空 |

### 2.3 架构上下文对齐协议（Context Before Code）

| 步骤 | 动作 | 约束 |
|---|---|---|
| 1 | 声明本次变更在架构中的**位置**（层/模块/边界） | MUST 用既有架构词汇，不新造概念 |
| 2 | 列出**受影响的对外契约**与依赖方向变化 | MUST 逐一列出；无变化也要显式写"无" |
| 3 | 与不可委托区清单**比对** | MUST 逐 zone 判定（触及/未触及） |
| 4 | 触及者转为"提案 + 人工决策点"，不进入实现 | NEVER 先改后报 |
| 5 | 未触及者记录对齐结论，进入 Phase 2 | MUST 留痕 |
| **新通道纪律 MUST 同时钉「复用清单 + 禁止清单」**（★v0.58） | 新增对外通道（新入口 / 新 CLI / 新集成）时，卡口 MUST **同时**钉：① **复用清单**（角色 / 校验 / 审核 / 阈值各调哪个既有函数）；② **禁止清单**（MUST NOT 自造第二套实现） | 只给禁止清单 ⇒ 违反（留下"自己写一份看起来更简单的实现"的缺口） |
| **被外部程序调用的接口改造 MUST 先冻结「契约面」**（★v0.58） | 改造由**其它程序（非人手工）**调用的脚本 / CLI 时，MUST 先枚举并冻结**契约面**（参数形态、退出码语义、被解析的关键输出串、stdout 结构）；实现可重写但契约面 MUST **逐字保留** | 未冻结就动实现 ⇒ 违反（"调用方无需改代码"只是口头承诺） |

### 2.6 改动足迹与复杂度预算（★v0.7）

> 来源：外部公开实践准则（由 Karpathy 对 LLM 编码陷阱的观察归纳的"克制型"行为准则，社区公开仓库 `multica-ai/andrej-karpathy-skills`，MIT）。
> 两类通病：① **越界改动** —— 顺手"改进"相邻代码/注释/格式，甚至重构没坏的东西，使改动集混入与请求无关的变化；
> ② **过度工程** —— 为一次性场景造抽象、加不被要求的"灵活性/可配置性"、替不可能发生的场景写错误处理。

**A. 改动足迹（Change Footprint）**

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| 逐行可追溯 | **每一行改动 MUST 可直接追溯到本轮请求** | 追溯不出的改动 ⇒ 撤回 |
| 不顺手改 | MUST NOT 顺手"改进"相邻代码、注释、格式；MUST NOT 重构未损坏的部分 | 混入无关变更 ⇒ 违反 |
| 沿用既有风格 | 既有代码风格 MUST 被沿用（即使实现者会写成别的样子） | 风格统一优先于个人偏好 |
| 死代码只提不删 | 与请求无关的死代码 MUST 仅**报告**，MUST NOT 删除 | 删除 ⇒ 违反 |
| 孤儿自清 | **因本轮改动**而变为未使用的引用/变量/函数 MUST 清理 | 留下孤儿 ⇒ 违反 |

**B. 复杂度预算（Complexity Budget）**

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| 不做投机设计 | MUST NOT 实现未被要求的功能，MUST NOT 加未被要求的"灵活性/可配置性" | 违反 ⇒ 撤回 |
| 一次性不抽象 | 一次性用途 MUST NOT 建抽象层（抽象 MUST 有契约或复用证据支撑） | 违反 ⇒ 撤回 |
| 不写不可达分支 | 为"不可能发生的场景"写错误处理 MUST NOT（不可达分支即噪声） | 违反 ⇒ 删除 |
| 有更简解须提出 | 存在明显更简单实现时 MUST 主动提出（行使反驳权），MUST NOT 静默照写复杂版 | 未提出 ⇒ 违反 |
| 体量压缩检验 | 实现体量明显超出问题所需（数量级级别）时 MUST 重写为更简形态 | 例外须记录理由 |
| 复杂度过高判据 | 检验问句：**资深工程师会不会说"这太复杂了"** ⇒ 会则简化 | 不可判定 ⇒ 改判据 |

> 与 §2.4 的关系：准入判"**能不能碰**"，本节判"**碰了多少、写得多复杂**" —— 同属变更边界，维度不同（许可 vs 足迹/体量）。

### 2.4 变更准入（Change Admission）

| 变更类型 | 准入判定 | 处置 |
|---|---|---|
| 区内改动 | 必然触及不可委托区 | 停止实现；产出提案（含理由/影响/回滚）；人类决策 |
| 边界相邻 | 可能间接影响 | 需要显式影响分析 + 人类确认 |
| 区内只读 | 仅读取不改 | 允许，但 MUST 记录读取目的 |
| 区外改动 | 不涉边界 | 按正常流程推进 |

### 2.5 边界漂移检查（Drift Check）

| 检查 | 频率 | 判据 | 处置 |
|---|---|---|---|
| 依赖方向漂移 | 每轮迭代 | 实际依赖 vs 声明边界 | 纠正依赖或正式调整边界（二选一） |
| 契约漂移 | 每轮迭代 | 对外契约变更是否走了准入 | 未准入的变更回退或补决策 |
| 隐形边界 | 每 Sprint | 代码中出现的"事实上的核心"是否已入清单 | 入清单或降级说明 |
| 例外累积 | 每 Sprint | 例外是否变成常态 | 例外常态化 ⇒ 重审该 zone 或流程 |

**C. 响应契约足迹（Response-Contract Footprint，★v0.54）**

> 来源：真实缺陷回溯 —— 某"只该影响少数行"的标记功能，给模型新增了 3 个 `bool/int` 派生字段却**未默认隐藏**，
> 于是**每一行**（含与该功能无关的行）的序列化响应都凭空多出 `xxx:false` / `yyy:0`。
> 不报错、不影响业务，但下游的**键集 / schema 校验 / 快照比对**已与原版不同 —— 典型"契约被悄悄改宽"。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| 增量默认隐藏 | 新增**可选 / 派生**输出字段（标记、统计、派生视图键）MUST 默认隐藏（序列化 `omitempty` / 条件回键） | 无条件输出 ⇒ 违反 |
| 无变化逐字一致 | **无标记、无变化**的行，其序列化输出 MUST 与改动前**逐字一致** | 多出键 / 多出值 ⇒ 违反 |
| 真值不得被吞 | 隐藏 MUST 只作用于"无值"态（`false` / `0` / 空串）；**有值 MUST 照常出现** | 隐藏吃掉真值 ⇒ 违反 |
| 条件回键同源 | 手工拼装的响应视图 MUST 与结构化序列化**同判据**（都按"有无标记"决定回不回键） | 一处有键一处无 ⇒ 违反 |
| 快照断言 | 该要求 MUST 由**序列化快照断言**覆盖：构造"无标记 / 有标记"两类输入，断言键集差异**恰好**为新增字段 | 只断言"有值时有键" ⇒ 违反 |
| NEVER | NEVER 让"只该影响少数行"的功能把**所有行**的响应、**存储契约**（表结构 / 键集 / 字段语义）或**变更时间戳**改宽；NEVER 用"新增字段无害"当理由（下游键集 / schema / 快照 / 审计排序都会变）；NEVER 为**诊断 / 可观测性**新增主体表字段或让采集循环每轮重写主体行 —— 诊断信息 MUST 优先走既有**低代价载体**（日志 / 只读查询接口）（★v0.99 扩适用范围：原只覆盖**响应契约**，未覆盖**存储契约与热点行写入**） | — |

> 与相邻条款的分工：`extensions/01` **L5 最小暴露**管**安全面**（不得多暴露数据）；本条管**契约面**（不得多增字段）；
> `§2.6 A 改动足迹`管**代码面**（不得多改行）。三者合起来 = "**改动不得溢出到无关面**"。

### 2.7 两轴独立演进（桥接）（★v0.88）

> 来源：项目侧反向演进（公开重构模式知识库的模式共性提炼，经人工确认入塔）。
> 重叠核对（C5）：本文件既有条目管**分层**与**变更足迹**，未钉「变化维度分解」⇒ 新增小节。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| **两轴 MUST 可独立演进** | 同一抽象沿**两个变化维度**各自扩展时，MUST 拆成两根独立可演进的轴（组合用装配/委托表达），MUST NOT 让一个实现体沿两轴出现 **m×n 组合变体**（枚举×枚举的笛卡尔展开） | 新增一轴的一个取值导致另一轴**全部**既有取值都要新增对应实现 ⇒ 违反（改一轴被迫全量改另一轴） |
| **机械判定** | 按维度命名/分支检索组合变体（"轴A取值 × 轴B取值"的展开命中）即命中；某轴仅 1 个取值时 MUST NOT 拆（守 `extensions/04` §2.5a 单实现禁令） | 判据不可检索 ⇒ 违反 |

> 与 §2.6 的分工：§2.6 管**改了多少**（足迹/体量）；本节管**沿哪几根轴长**（维度分解）。
> 触发信号：同一结构/函数族里出现"两类互不相干的关键词自由组合"（典型：两维 if 嵌套的展开）。

### 2.8 网状依赖收敛（中介者）（★v0.88）

> 来源：同上（经人工确认入塔）。重叠核对（C5）：`core/02` §2.2b 管**口径**唯一、本文件 §2.1 管**不可委托区**，
> 均未钉「调用拓扑形状」⇒ 新增小节。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| **星型优于网状** | 同层对等模块间 **N×N 直接互调** MUST 收敛为**星型**（统一经由一个协调点/编排层），MUST NOT 让对等模块两两直连形成网状 | 新增一个模块需要改动**全部**既有对等模块（每个都认识彼此）⇒ 违反 |
| **机械判定** | 调用图按**文件对**统计直接互调；对等集合规模 n 的直接互调对数接近完全图（≥ n(n−1)/2 的一半）即命中 | 判据不可统计 ⇒ 违反 |
| **协调点 MUST NOT 变新枢纽** | 收敛后的协调点 MUST 只做**编排/转发**，MUST NOT 吸收对等模块的业务语义（否则网状只是换个地方长回去） | 协调点含对等模块的业务分支 ⇒ 违反 |

> 触发信号：一次用例要靠"你调我、我调他"才能完成（编排逻辑散落在对等方里互相调用、互相同步状态）。

### 2.7a 状态/枚举迁移 MUST 表驱动单一真源，守卫挂咽喉（★v0.89）

> 来源：项目侧反向演进（某轮状态迁移表实证，经人工确认入塔）。
> 重叠核对（C5）：`core/02` §2.2b 管**口径集合**唯一、形态目录 **H5** 管**类型分发**，均未钉
> 「**迁移合法性**的表驱动与守卫挂载点」⇒ 新增小节（与 §2.7/§2.8 同属架构模式族）。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| **迁移 MUST 表驱动** | 实体的状态迁移合法性 MUST 收敛为**一张迁移表**（from → 合法 to 集合）作为唯一真源，MUST NOT 散落在各写入点的条件判断里；表内容 MUST 由**现有写入点逐一取证归纳**，MUST NOT 预设"将来可能有"的边 | 新增一个写入点需要另行口耳相传"哪些迁移合法" ⇒ 违反 |
| **守卫挂咽喉** | 迁移守卫 MUST 挂在**唯一咽喉**（乐观锁 CAS / 收口函数 / 单一更新入口）上 **fail-closed**（非法迁移直接报错、不触副作用）；咽喉调用点 MUST 全部合法 ⇒ 守卫上线零行为变化 | 守卫上线即出现既有合法路径报错 ⇒ 表取证不全，先修表再上线 |
| **存量直写点豁免登记** | 未经咽喉的**直写点**（绕过咽喉的部分更新/裸写字段）MUST 登记为收敛目标（豁免清单**只减不增**），MUST NOT 强改存量直写行为（那是行为变更），也 MUST NOT 假装不存在 | 直写点无登记 ⇒ 违反；借"收敛"之名顺手改行为 ⇒ 违反 |
| **与终态判定互证** | 迁移表 MUST 与既有终态/谓词真源**互证**（终态 MUST 无出边）；枚举扩张时 MUST 复核迁移表与全部谓词，MUST NOT 靠 else 兜底 | 终态出现出边，或两真源矛盾 ⇒ 违反 |

> 机械判定：迁移表为可枚举数据（map/表）；咽喉守卫在场断言（咽喉函数体引用判定函数）；
> 直写点豁免清单只减不增。
> 触发信号：状态字段驱动的散点判断（`== X` / `!= Y` 链）出现在 ≥3 个写入点；或 CAS 更新函数存在
> 但不校验迁移合法性。

### 2.9 一次性迁移的清理步骤 MUST 退役（★v0.90）

> 来源：项目侧反向演进（启动期遗留表清理实证——一次性数据清理被写成常驻启动步骤、每轮启动重复执行销毁语句，经人工确认入塔）。
> 重叠核对（C5）：`extensions/01` 管**安全门与输入边界**，本文件 §2.1 管**不可委托区分类**、§2.7a 管**状态迁移合法性**——
> 均未钉「**迁移清理步骤的生命周期**」⇒ 新增小节（数据模型红线族）。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| **清理 MUST 一次性化** | 迁移附带的数据清理/销毁步骤（删表 / 清空 / 重置）MUST 定性为**一次性**操作：随迁移首次执行完成后 MUST **退役**为显式运维脚本或人工操作，MUST NOT 常驻启动路径 / 热路径 / 定时任务 | 一次性清理每轮启动（或每轮任务）重复执行 ⇒ 违反 |
| **常驻路径零销毁** | 常驻路径 MUST NOT 含数据销毁语句（DROP / TRUNCATE / 无界 DELETE）；孤儿/遗留对象**保留无害**（零代码引用），MUST NOT 由运行流程静默销毁——宁可留孤儿，不可赌数据 | 启动或任务日志出现销毁动作 ⇒ 违反 |
| **退役 MUST 留痕** | 清理步骤退役时 MUST 留痕：对象清单 + 退役原因 + 人工执行指引；MUST NOT 无声消失（后人需要知道"这些对象是什么、为什么留下"） | 清理逻辑无声消失且无指引 ⇒ 违反 |

> 机械判定：启动/迁移路径源码扫描销毁语句（删表/清空）命中 = 0（剥注释口径，沿 §2.2a）；
> 退役留痕在场断言。
> 触发信号：启动或任务日志出现 DROP/清理字样；迁移函数体内含销毁语句；或迁移注释自称"一次性"却在常驻函数里。

### 2.10 基建句柄获取 MUST 经单一出口门面（★v0.90）

> 来源：项目侧反向演进（表现层直连基础设施句柄包、数十处散点耦合实证，经人工确认入塔）。
> 重叠核对（C5）：`core/02` 管**口径**唯一、§2.8 管**调用拓扑形状**、§2.1 管不可委托区——
> 均未钉「**句柄获取**的单一出口」⇒ 新增小节。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| **消费方 MUST NOT 直 import 基建句柄包** | 表现层/业务层消费方 MUST NOT 直接 import 基础设施**句柄/连接**包（全局单例、连接池句柄）；句柄获取 MUST 经**单一出口门面** | 任一消费方 import 基建句柄包 ⇒ 违反 |
| **门面 MUST 薄转发** | 门面 MUST 只做转发（零业务逻辑、零缓存、零装饰）——句柄之下的分层重构（repository 化等）另行推进，MUST NOT 借门面顺手重设计 | 门面含业务分支 ⇒ 违反（把重构混进门面，改动足迹越界） |
| **机械判定** | 消费方包源码逐文件扫描 `import 基建句柄包` 命中 = 0；门面导出面与既有调用形态一一对应（改名牌） | 判据不可扫描 ⇒ 违反 |

> 触发信号：同一基建句柄包被 ≥3 个消费方各自 import；或消费方出现"句柄全局变量"直接引用。
> 与 §2.8 的分工：§2.8 管**模块间调用拓扑**；本节管**对基础设施的句柄依赖方向**（消费方 → 门面 → 基建包）。

### 2.11 缺省回落 MUST NOT 跨越隔离域（★v1.00）

> 来源：真实缺陷回溯（去业务化）—— 某访问器按"环境 / 租户 / 实例类型"取值，`default` 分支**回落到主域**
> （当时该集合只有两个合法取值，回落是"便利兜底"）。集合后来扩容到四个取值，新增项**未接线** ⇒
> 它们的请求**静默落到主域**：不报错、不告警、审计上看起来一切正常，而实际是**跨隔离域的读写**。
> 判定：这不是"少写一个 `case`"，而是**回落方向越界** —— 兜底值落在**隔离强度更低 / 范围更广**的域里时，
> "未接线"就等价于"越权访问"。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| 回落同域 | 可选域的缺省回落 MUST 落在**同一隔离域**内（同一环境 / 同一租户 / 同一权限档）；MUST NOT 回落到范围更广、权限更高、或另一个隔离域的默认值 | 回落到更宽 / 更高权的默认值 ⇒ 违反（未接线 = 静默越权） |
| 未命中显式失败 | 集合的"未命中" MUST **fail-closed**（显式错误 + 日志），MUST NOT 用 `default` / `else` 静默兜底；确需兜底时 MUST 声明"该兜底同域"并留断言 | `default` 静默兜底 ⇒ 违反（越权面与"正常"不可区分） |
| 扩容同轮接线 | 可选域**扩容**（新增合法取值）时，其**全部消费面**（访问器 / 映射 / 判定 / 展示 / 凭据路由）MUST 同轮接线并**显式拒绝**未知值；MUST NOT 只改真源 | 只扩充取值集合而不接线 ⇒ 违反（新值静默走兜底） |
| 机械判定 | 访问器 MUST 有"未知取值 ⇒ 拒绝"用例；隔离域的默认值 MUST NOT 出现在 `default` / `else` 分支（扫源码即判） | 无未知值用例 ⇒ 违反（兜底方向无人守） |
| NEVER | NEVER 让兜底分支跨隔离域；NEVER 只在真源扩充取值而不排查消费面 | — |

> 与 §2.10 的分工：§2.10 管**句柄从哪来**（单一出口门面）；本节管**拿不到时给什么**（回落方向）。
> 与 `extensions/01` §2.1b 的分工：那里管**范围默认值是否放大作用域**（读 / 写 / 批量 / 导出）；本节管**取值未命中时的兜底方向**（fail-open vs fail-closed）。

## 3. 输入 / 动作 / 输出物

| 项 | 内容 |
|---|---|
| 输入 | 变更计划、架构现状、不可委托区清单 |
| 动作 | 位置声明 → 契约影响列举 → 逐 zone 比对 → 准入判定 → 漂移检查 |
| 输出物 | 架构对齐声明、准入判定结论、提案（如需人工决策）、漂移报告 |

## 4. 硬性约束

- **MUST**：A 每次写码前完成对齐声明；B 逐 zone 判定并留痕；C 例外流程写明审批与证据；D 漂移项在下一轮开工前处置；E **每一行改动可追溯到本轮请求**（★v0.7）；F 复杂度控制在问题所需的**最小形态**（★v0.7）；G 一次性迁移的清理步骤随迁移完成**退役**并留痕，常驻路径零销毁语句（★v0.90）；H 基建句柄获取经**单一出口门面**（薄转发），消费方不直 import 基建句柄包（★v0.90）；I 可选域的缺省回落 MUST 落在**同一隔离域**，集合"未命中" MUST **fail-closed**（MUST NOT 用 `default` / `else` 静默兜底），可选域扩容 MUST 同轮接线**全部消费面**并显式拒绝未知值（★v1.00）。
- **NEVER**：A 在未对齐状态下开始实现；B 由 Agent 自主修改不可委托区；C 以"只是小改动"绕过准入；D 把新造的核心概念悄悄写进代码却不入清单；E **顺手改动**相邻代码/注释/格式，或删除与请求无关的死代码（只提不删）（★v0.7）；F 为一次性场景造抽象、加未被要求的"灵活性/可配置性"（★v0.7）；G 以"反正数据已迁走"为由保留常驻数据销毁步骤（★v0.90）；H 绕过门面直取基建句柄、或往门面里塞业务分支（★v0.90）；I 让 `default` / `else` 回落到更宽或更高权限的隔离域，或只在真源扩充取值而不排查消费面（★v1.00）。

## 5. 检查清单（Phase 3 退出前逐项打勾）

- [ ] 对齐声明含：架构位置、受影响契约、逐 zone 判定结论
- [ ] 触及不可委托区的改动**未**进入实现，已转提案
- [ ] 每个 zone 都有 `rationale` 与 `exception_path`
- [ ] 依赖方向变化已显式评估（含"无变化"的显式记录）
- [ ] 本轮未出现未准入的对外契约变更
- [ ] 漂移报告中的未决项已排入下一轮
- [ ] 每一行改动都能直接追溯到本轮请求；无"顺手改进"式的无关变更（★v0.7）
- [ ] 复杂度已用"资深工程师会不会说太复杂"自检；无投机性功能/抽象/不可达分支（★v0.7）
- [ ] **响应契约足迹已核对**：新增可选字段默认隐藏；**无标记行输出与改动前逐字一致**；有值不被隐藏吞掉；手工拼装视图与结构化序列化同判据（★v0.54）
- [ ] 可选域的**缺省回落**已核对同域（未回落到更宽 / 更高权限的隔离域）；"未命中"为 **fail-closed**，无 `default` / `else` 静默兜底；扩容时全部消费面已同轮接线并有"未知取值 ⇒ 拒绝"用例（★v1.00）

## 6. 反模式

| 反模式 | 现象 | 纠正 |
|---|---|---|
| 先改后报 | 改完架构再说"顺便调了下结构" | 回退并走准入 |
| 边界膨胀 | 什么都说不可委托 | 按"破坏后是否可局部回退"筛选 |
| 例外常态化 | 每个需求都走例外 | 重审 zone 定义或流程 |
| 口头边界 | 边界只存在于某人脑子 | 落文档 + 可检测判据 |
| 顺手改进（★v0.7） | 变更集里混入与请求无关的格式/注释/重构 | 撤回无关改动，或另开一轮请求 |
| 过度工程（★v0.7） | 问题所需 100 行却写 1000 行，附带一堆"可配置" | 按复杂度预算逐项删减 |
| 契约改宽（★v0.54） | 新标记字段不默认隐藏 ⇒ **所有行**的响应都多出键（值恒空），下游键集/schema/快照随之变化 | 可选字段默认隐藏 + 无变化行逐字一致 + 序列化快照断言 |
| 常驻销毁（★v0.90） | 一次性迁移清理写成启动/热路径常驻步骤 ⇒ 残留孤儿数据每轮被静默销毁 | 清理退役为显式运维操作 + 常驻路径零销毁语句 + 退役留痕 |
| 句柄散连（★v0.90） | 消费方各自 import 基建句柄包 ⇒ 连接管理/拦截/替换无法单点收口，耦合散点持续扩散 | 句柄获取单一出口薄门面 + 消费方 import 扫描归零 |
| 跨域兜底（★v1.00） | 可选域取值未命中时 `default` 回落到**更宽 / 更高权限的域**（如主域）⇒ 扩容后新增取值静默跨隔离域读写，零报错、审计看起来正常 | 回落同域 + 未命中 fail-closed + 扩容同轮接线全部消费面 + "未知取值 ⇒ 拒绝"用例 |
