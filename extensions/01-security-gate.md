# 01. 安全关卡与实证审计（VibeGuard）

> 理论支撑：P6（VibeGuard）、P10（Understanding the (In)Security of Vibe-Coded Applications）
> 对抗失效：**F5 安全与配置失控**
> 落地阶段：Phase 3（独立关卡，全量执行）

## 1. 目标

为 AI 生成代码设立**独立于功能验收**的深度安全关卡，专门覆盖传统静态分析与密钥扫描**容易漏掉**的失效模式。
典型教训（P6）：真实事故根因不是逻辑错误，而是**发布/打包配置错误**（误带源码映射文件，暴露数十万行私有代码）——
这类故障**不在**通用 SAST 的射程内。

## 2. 核心机制：四类关卡（每次全量）

### 2.1 L1 越权访问（Broken Authorization）

| 检查项 | 判定 | 证据要求 | 处置 |
|---|---|---|---|
| 入口鉴权 | 每个对外入口是否都有明确鉴权判定 | 入口清单 + 鉴权位置 | 缺失 ⇒ 阻断 |
| 越权路径 | 是否可绕过身份/角色直接触达敏感操作 | 逐入口角色矩阵比对（P10 高危类） | 可绕过 ⇒ 阻断 |
| 默认放开 | 是否存在"默认允许、特例禁止"的判据 | 默认值与例外清单 | 默认放开 ⇒ 阻断 |
| **范围全集态**（★v0.30） | 范围维度（环境 / 租户 / 项目 / 归属）**同时**被用作写 / 批量 / 导出作用域时，是否提供「全部 / 不限」态，或其**默认值**是否为全集 | 全集态**可达**或**作为默认**；取数用"有值才传参"的条件式（空 ⇒ 不过滤） | 命中 ⇒ 阻断（作用域**静默放大**：读侧便利连带写侧 —— 细则见 §2.1b） |
| 对象归属 | 是否校验"资源是否属于当前主体" | 归属校验位置 | 仅校验身份未校验归属 ⇒ 阻断 |

### 2.1a 权限收口粒度（按动作，★v0.10）

> 来源：真实缺陷回溯 —— 权限收口**按模块 / 路由组**划分（而非按**动作**），会同时制造两个**方向相反**的缺陷：
> ① **过严**：同一功能域的**读**操作被绑上该域**写**操作的门槛 ⇒ 合法角色无法完成本职（可用性缺陷，
> 却常被当成"设计如此"长期留存，甚至表现为"页面整片空白/接口报错"这类**表象与根因相距很远**的现象）；
> ② **放宽越界**：为解可用性而把整组门槛下调 ⇒ **连写操作一起放开**（安全缺陷）。
> 关键认识：**"过严"与"过松"是同一枚硬币的两面**，都源于"收口粒度错位"。
>
> **追加来源（★v0.81）**：真实缺陷回溯 —— 某页面的写操作**后端**已按角色收口，**前端控件**却对**所有角色**可见 ⇒
> 使用者看到可点控件、点下去才 403：既像"功能坏了"，又把"能不能做"表达成"点了才知道"。
> 关键认识：**权限门有两面** —— **实施面**（接口是否拦）与**表达面**（控件是否可见 / 是否就地说明）；
> 只做实施面时，缺陷表现为"功能坏了"而不是"权限不足" ⇒ 使用者**连取证都无从开始**。

| 检查项 | 判定 | 处置 |
|---|---|---|
| 按动作定级 | 权限门槛 MUST 由**动作语义**决定（读 / 写 / 删 / 授权 分别定级），MUST NOT 由"路由组 / 模块 / 页面"**连带**决定 | 读操作要求了写权限 ⇒ 阻断 |
| 放宽精确到动作 | 收口调整 MUST **只针对被报告的动作**；同域其它动作的门槛 MUST NOT 被连带改动 | 连带放宽 ⇒ 阻断 |
| 过严也记缺陷 | 合法角色被拦 MUST 记为缺陷（与越权**同级**），MUST NOT 以"更安全"为由接受 | 不记录 ⇒ 阻断 |
| 双向留证 | 调整 MUST 同时给出"目标动作已放开"**与**"同域其它动作仍收口"两份证据 | 只证一侧 ⇒ 阻断 |
| **可见面 == 可操作面**（★v0.81） | 动作的**可见性** MUST 与**可操作性**同门：无该动作权限的角色 MUST NOT 看到可点控件（**不可见**，或**禁用 + 就地说明原因**）；两层 MUST 各自可核（**控件是否在角色门内** + **写接口是否 403**） | 控件对所有角色可见、点击才 403 ⇒ 阻断 |
| **受限动作 MUST 以说明呈现**（★v0.81） | 受权限限制的动作 MUST 在界面上**说清**（说明文案 + 原因；就地文案或悬浮提示至少其一），MUST NOT 以**报错**充当说明 | 只留报错、无说明文案 ⇒ 阻断 |

### 2.1b 范围收口：全集态与最窄默认（★v0.30）

> 来源：真实缺陷回溯 —— 某**范围维度**（环境 / 租户 / 项目 / 归属）在界面上提供「全部 / 不限」，
> 且该维度**同时**是**批量 / 变更 / 导出**的作用域；"不过滤"既被当作**默认**，也被当作**合法选择**。
> 关键认识：**读侧的便利会传染到写侧** —— 同一个控件、同一个维度值，**读**时是"看全貌"，**写**时就是"改全部"；
> 而"维度为空 ⇒ 不施加条件"是最省事的实现，**没有任何信号**（静默类）。

| 检查项 | 判定 | 处置 |
|---|---|---|
| 全集态不可达（写作用域） | 该维度**同时**用于写 / 批量 / 导出作用域 ⇒ 「全部 / 不限」态 MUST NOT **可达**（读侧需保留便利时，写侧 MUST 独立收窄） | 可达 ⇒ 阻断 |
| 默认值取最窄 | 维度筛选的**默认值** MUST 为**最窄**作用域，MUST NOT 以"全集"为默认 | 默认全集 ⇒ 阻断 |
| 维度值恒传 | 取数 MUST **恒传**维度值；MUST NOT 用"有值才传"的**条件式**（空 ⇒ 不过滤 ＝ **静默全集**） | 条件式传参 ⇒ 阻断 |
| 异域入参收敛或失败 | 入参落在取值域**之外** ⇒ MUST 收敛到**最窄**作用域或**显式失败**，MUST NOT 静默落全集 | 静默落全集 ⇒ 阻断 |
| **多目标同域**（★v0.31） | 一次操作的**多个目标** MUST 同属**同一执行域**（同一集群 / 分区 / 租户 / 归属域） | 跨域放行 ⇒ 阻断 |
| 禁止自动拆分 | 目标跨域时 MUST NOT 由系统**自动拆分**为多次操作、MUST NOT **就近归并**到某一域 | 自动拆分 / 就近归并 ⇒ 阻断 |
| 跨域失败须附处置 | 跨域**显式失败**时 MUST 给出**可执行的处置**（按域拆分 + 示例），MUST NOT 只报"不允许" | 只报结论 ⇒ 阻断 |
| **不可逆批量动作三件套**（★v0.57） | 清理 / 删除 / 归档 / 扣减等**不可逆批量动作** MUST 同时满足：① 由**可运维的配置真源**驱动（改配置即生效，MUST NOT 只能改代码发版）；② **默认值 = 不执行**；③ **触发面唯一**（后台调度 / 运维通道），MUST NOT 由**请求方 / 代理 / 前端**直接触发 | 默认执行 / 请求方可触发 / 只能改代码 ⇒ 阻断 |
| **「不可判定」一律落不执行侧**（★v0.57） | 前置判定为"不可判定"（读不到配置 / 解析失败 / 状态查不到 / 无判定手段 / 时间不可判）时，动作 MUST **不发生**，且 MUST **分类留痕**（可区分"被保留"与"没轮到"） | 落执行侧 ⇒ 阻断（把"不知道"当"可以删"；与 `core/02` §2.2d ★v0.57 成对） |
| **空值即不过滤 MUST 区分「未指定」与「不匹配」**（★v0.58） | 当**范围 / 过滤参数**的空值语义是"不过滤（全量）"，且其取值来自**身份或上下文**（账号 / 租户 / 环境）时，空值 MUST 被当作**匹配不到任何行**（fail-closed）；"允许全量" MUST 由调用方**显式**决定（如由权限谓词给出） | 因"取值为空"退化成全量 ⇒ 阻断（越权读全量） |
| **不可逆动作 MUST「可见性先于清理」**（★v0.58） | 对**不可逆**资源（文件 / 外部记录 / 已发布配置）的清理，MUST **先提供只读可见性**（清单 + 判定依据 + 不可判定项**单列**），把"删除"留给人工 / 显式策略 | 自动化在"看不清影响面"时删除 ⇒ 阻断 |

> 自查方法（可复用）：对每个范围维度问一句「这里的『全集』到底是**只读便利**，还是**连写作用域一起放大**？」
> —— 答"写也一起"时，全集态 MUST 从**默认值**与**可达状态**两处**同时**移除（只删其一 ⇒ 另一路径照旧放大）。
> **追加自查（★v0.31）**：把一次操作的**全部目标**列出来，逐个标注"它属于哪个**执行域**" —— 出现**两种及以上**取值时，适用上表「**多目标同域**」。
> **追加自查（★v1.00）**：本表「异域入参收敛或失败」管的是**入参**落在取值域之外；与它相邻的另一个越权面是**缺省回落方向** ——
> 访问器 / 路由在选择"环境 / 租户 / 实例类型"未命中时，兜底值 MUST NOT 落在更宽或更高权限的域（细则见 `extensions/02` §2.11）。

### 2.2 L2 凭据与配置泄漏（Secret & Config Leakage）

| 检查项 | 判定 | 处置 |
|---|---|---|
| 硬编码凭据 | 源码/脚本/构建产物中是否存在密钥、口令、令牌 | 阻断并轮换 |
| 测试凭据进产物 | 测试密钥/调试开关是否进入发布物 | 阻断 |
| 不安全端口/开关 | 是否开放调试端口、关闭安全校验 | 阻断 |
| 日志泄漏 | 日志是否打印敏感原文（凭据、令牌、个人数据） | 阻断并整改 |

### 2.3 L3 发布与打包配置（Release/Packaging）

| 检查项 | 判定 | 处置 |
|---|---|---|
| 产物内容清单 | 发布物是否只含运行时必需文件 | 多余文件 ⇒ 阻断 |
| 源码映射/调试符号 | 是否随包分发（P6 事故形态） | 阻断 |
| 版本与指纹 —— **且指纹 MUST 可复现**（★v0.64） | 产物是否带可追溯版本与校验指纹，**且该指纹 MUST 能由同一输入状态重建得到同一值**：① 构建输入 MUST **全量固定**（含易漂移的元数据：构建标识 / 时间戳 / VCS 状态 / 路径）；② 已登记的**历史指纹 MUST 冻结不回改**（新技术与旧指纹不可比时，只在**新**记录里登记新指纹）；③ 校验 MUST 覆盖**两处** —— **工作区产物 == 登记值**，且**版本库内产物 == 登记值**（"仓库内产物 == 登记值"是 SCM 侧不变量，MUST NOT 只核工作区文件） | 缺失 ⇒ 阻断；**不可复现 ⇒ 阻断**（不可复现的指纹无法被任何人复核 ⇒"回填指纹"退化为一次性快照，校验点**静默失效**；每版回改历史指纹 = 伪造记录） |
| 平台与目标一致 | 目标平台/架构与声明一致（如仅出某平台产物而漏出另一平台） | 不一致 ⇒ 阻断 |
| **核验标记类型**（★v0.3） | 产物**内嵌核验标记** MUST 为**字符串字面量**（版本串、日志文案、对外错误码等）；**标识符**（函数名 / 常量名 / 变量名）在符号被剥离的构建（如链接期 `-s -w`、符号裁剪）后**不会出现** ⇒ MUST NOT 作为标记 | 用标识符作标记 ⇒ 阻断（会给出"假不命中"结论，进而误判"未生效"） |
| **负例核验**（★v0.3） | 核验 MUST 同时包含**负例**：上一版版本串 / 已移除的能力 MUST **不命中** | 只做正例 ⇒ 阻断（无法证明"确实切换/确实移除"） |
| **持久化目录锚定绝对路径**（★v0.57） | 程序自有的**持久化 / 缓存 / 留档目录**缺省 MUST 为**绝对路径**（锚定应用根或显式配置；覆盖口留在**配置层**），MUST NOT 以"相对当前工作目录"为缺省 | 相对缺省 ⇒ 阻断（同一程序以不同方式拉起（手工 / 服务管理器 / 计划任务）时工作目录不同 ⇒ 文件散落多处且**无信号**，清理 / 备份口径随之失效） |
| **随仓脚本 MUST 有「可执行面」判据**（★v0.58） | 随仓交付的**可执行脚本** MUST 有一组可机械判定的"可执行面"判据：① 含非 ASCII 的 `.ps1` MUST 带 UTF-8 BOM（否则某类 shell 按本地编码解析 ⇒ 语法错）；② `.sh` MUST 用 LF（CRLF 使 shebang 失效）；③ 调用外部工具链 MUST **预检可用性**，缺失 ⇒ 明确失败 + 修正指引 | 缺任一项 ⇒ 阻断（"看起来没问题、一跑就错"） |
| **能力交付 MUST「真源 + 镜像 + 一致性判据」三件套**（★v0.58） | 同一交付物需同时存在于**运行时加载位置**与**版本化仓库**时，MUST 明确**真源**、提供**逐字节镜像**，并用卡口强制"文件清单 + 逐字节一致"（真源不在场 ⇒ **skip 而非绿灯**） | 两边各改一点 / 多出未登记文件 ⇒ 阻断 |

### 2.3a 生效链路三环核验（Release Effectiveness Chain，★v0.6）

> 来源：真实缺陷回溯 —— 反复出现同一类误判：**把"改动已合入"当成"改动已生效"**。
> 链路上有三道闸：① 改动是否进入**本次产物**（构建期内嵌的资源/模板/静态文件尤甚：源文件改了 ≠ 产物改了）；
> ② 产物是否**已下发**到运行环境（并完成重启/重载）；③ 运行侧是否仍在用**旧副本**（客户端/中间层/进程缓存）。
> 任一环未验，"已修复"的结论都可能是错的。

| 环 | 核验什么 | 判定 | 处置 |
|---|---|---|---|
| R1 进产物 | 改动是否真的被打进**本次**产物（含"改了源文件必须重新构建"这类结构性前提） | MUST 用**产物侧证据**核验（内嵌标记/指纹/摘要/构建时间），MUST NOT 只看源码 | 未进产物 ⇒ 阻断（禁止宣称已交付） |
| R2 已下发 | 产物是否部署到目标环境并生效 | 运行侧可查询的版本/指纹与产物一致 | 不一致 ⇒ 阻断 |
| R3 引用已失效 | 缓存是否会让旧副本继续生效 | MUST 明确**缓存失效动作**（强刷/指纹化路径/缓存头）并写入核验步骤 | 未写明 ⇒ 阻断（"已修复"但使用者仍见旧行为） |

> 可复用自查法：**产物构建时间 vs 源文件修改时间** —— 产物早于源码 ⇒ 必未生效。

### 2.4 L4 外部输入信任边界（Input Trust Boundary）

| 检查项 | 判定 | 处置 |
|---|---|---|
| 输入校验 | 所有外部输入是否在边界处校验（类型/范围/长度） | 缺失 ⇒ 阻断 |
| 注入面 | 拼接式构造是否可能被外部输入污染 | 可能 ⇒ 阻断 |
| 反序列化与解析 | 不可信数据的解析是否有失败路径 | 无失败路径 ⇒ 阻断 |
| 错误回传 | 是否向前端回传底层错误原文/内部结构 | 回传 ⇒ 阻断（只回粗分类） |

### 2.5 L5 集合接口最小暴露（List/Collection Minimal Exposure，★v0.4）

> 来源：真实缺陷回溯（`extensions/05` 机制一）—— 同一实体在**列表**与**详情**两类接口上口径不一致：
> 详情必须给载荷，列表却"顺便"整单回传（含脚本、方案、可能含明文口令的载荷）。
> 关键认识：**UI 不渲染 ≠ 接口不回传** —— 页面看不出来、也没有任何信号，属**静默类暴露**。

| 检查项 | 判定 | 处置 |
|---|---|---|
| **载荷分离** | 大载荷 / 敏感载荷（口令、密钥、脚本、明细、长文本）MUST 只在**详情**接口回传；**集合/列表**接口只回标识与必要展示字段 | 列表回传载荷 ⇒ 阻断 |
| **口径单一真源** | 同一实体的载荷处理口径 MUST 由**单一真源**承担（一处函数/一处声明）；MUST NOT 在多处各自实现 | 多处各自实现 ⇒ 阻断（"改一处漏一处"） |
| **标记替代载荷** | 列表需要按类型区分时 MUST 回**标记位**（如 `is_x` 布尔），MUST NOT 回载荷本身 | 用载荷代替标记 ⇒ 阻断 |
| **全集合清单** | 所有集合形态接口（列表 / 搜索 / 导出 / 轮询 / 汇总）MUST 纳入自查清单，**不得只查最近改过的那一个** | 漏项 ⇒ 阻断 |

> 自查方法（可复用）：把同一实体的**全部**输出接口列出来，逐列标注"该字段为何必须在**这里**出现" —
> 答不出的字段即为过度暴露。

## 3. 关卡执行规则

| 规则 | 内容 |
|---|---|
| R1 **独立性** | 关卡与功能验收**分通道**执行；功能全绿 **≠** 关卡通过 |
| R2 **全量性** | 每次至少执行四类全部检查项；**禁止**只跑上轮命中项 |
| R3 **阻断性** | 命中 ⇒ 立即阻断；修复后**重跑全量**（不是只跑命中项） |
| R4 **不确定从严** | 无法判定 ⇒ 按更严一侧处置，并登记（依据 + 责任人） |
| R5 **可追溯** | 关卡报告须含：检查项、判定、证据位置、结论、责任人 |
| R6 **不可跳级** | 跳过关卡须书面决策并由人类责任人签字（默认禁止） |

## 4. 硬性约束

- **MUST**：A 四类 **+ L5 集合接口最小暴露**每次全量执行（★v0.4）；B 阻断后重跑全量；C 不确定项按更严一侧并登记；D 关卡结论分开出具；E 内嵌核验标记**只用字符串字面量**且**含负例**（★v0.3）；F **生效链路三环**（进产物 / 已下发 / 引用已失效）逐环有**产物侧证据**（★v0.6）；G 权限门槛**按动作定级**（读 / 写 / 删 / 授权分别定级），收口调整**只针对被报告动作**并给出**双向证据**（★v0.10），且**可见面 == 可操作面**（无权限 ⇒ 不可见，或禁用 + 就地说明原因）、受限动作 MUST 以**说明**呈现、MUST NOT 以报错充当说明（★v0.81）；H 集合型操作的**多目标 MUST 同域**，跨域 ⇒ **显式失败并附可执行处置**（★v0.31）。
- **NEVER**：A 以"功能已完成/时间紧"跳过关卡；B 把"未判定"记为通过；C 向前端回传底层错误原文；D 用"内部系统不用管安全"作为豁免理由；E 用**标识符**作为产物核验标记（符号剥离后必不命中 ⇒ 结论失真）（★v0.3）；F 以"改动已合入"替代"改动已生效"（★v0.6）；G 由"路由组 / 模块"连带决定权限门槛，或为解可用性而**连带放宽**同域其它动作（★v0.10），或让无权限角色看到可点控件（**可见面 ≠ 可操作面**）、把"能不能做"留给点击后的报错去说（★v0.81）；H **自动拆分**跨域的目标集合，或把它们**就近归并**到某一域（★v0.31）。

## 6. 反模式

| 反模式 | 现象 | 纠正 |
|---|---|---|
| 关卡装饰 | 报告写了"已检查"，无逐项判定 | 按 R5 重出报告 |
| 只跑命中项 | 修复一处就放行 | 按 R3 全量重跑 |
| 安全豁免惯例 | "这个模块特殊，不用查" | 豁免须书面决策，默认禁止 |
| 泄漏式排错 | 把底层错误原文回传前端方便调试 | 粗分类对外 + 详情落服务端日志 |
| 标识符当标记（★v0.3） | 用函数名/常量名核验产物内嵌 ⇒ 剥离后不命中，被误判为"没生效" | 改用字符串字面量，并加负例核验 |
| 只有源码没有产物证据（★v0.6） | "我改了源文件"即宣称已交付 | 按 §2.3a 取产物侧证据（R1/R2/R3） |
| 忘了缓存（★v0.6） | 已部署，但使用者仍见旧行为 | 核验步骤写明缓存失效动作 |
| 收口粒度错位（★v0.10） | 读操作被绑上写操作的门槛（合法角色被拦 ⇒ 表象是"页面空白/报错"，根因却在权限分组） | 按动作定级，调整只针对被报告动作 |
| 过严当设计（★v0.10） | 以"更安全"为由接受"合法角色无法完成本职" | 记为缺陷（与越权同级）并双向留证 |
| 权限只做一半（★v0.81） | **后端**已按角色收口、**前端控件**仍对所有角色可见 ⇒ 点了才 403，使用者以为"功能坏了" | 可见面与可操作面同门：不可见，或禁用 + 就地说明；限制以**说明**呈现 |
