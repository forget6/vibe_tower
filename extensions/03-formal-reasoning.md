# 03. 形式化状态机与演绎验证（Vibe Reasoning & Forge）

> 理论支撑：P8（Vibe Coding Needs Vibe Reasoning）、P11（Formal-Method-Guided Vibe Coding）、P2（FlowCheck）
> 对抗失效：**F3 隐性逻辑错误**、**F6 状态偏离**
> 落地阶段：Phase 3（约束累积台账）、Phase 4（不变量检查与证据链）

## 1. 目标

在关键流转逻辑上引入**轻量形式化**：让"内部状态是否发生未声明迁移"从**靠 reviewer 目测**，
变成**可被判定的检查**。核心洞察（P8）：LLM 难以调和**逐步累积的人类约束** ⇒ 必须把约束显式化并持续校验。

## 2. 核心机制

### 2.1 约束累积台账（Constraint Ledger）

| 字段 | 含义 | 硬性约束 |
|---|---|---|
| `constraint_id` | 稳定编号 | MUST 唯一 |
| `source` | 来源（哪个阶段/哪次对话/哪个缺陷） | MUST 可追溯 |
| `statement` | 约束陈述（可判定） | MUST 无模糊词 |
| `status` | `active`／`superseded`／`retired` | MUST 明确；被取代者保留记录 |
| `enforced_by` | 由什么检查强制（断言/不变量/关卡） | MUST 非空（无强制手段的约束是空话） |

> 关键：约束**只增不删**（可标记 `retired`）——历史约束被静默移除，正是"约束在传递中丢失"的主因。

### 2.2 状态机契约（State Machine Contract）

对每个关键状态机（有状态流转、并发、权限、额度/计数类逻辑）声明：

| 要素 | 内容 | 硬性约束 |
|---|---|---|
| 状态集合 | 全部合法状态 | MUST 穷举；含"终态"标记 |
| 初始态 | 从哪个状态开始 | MUST 唯一或明确集合 |
| 合法迁移 | `from → to [触发条件]` 列表 | MUST 逐条列出触发条件 |
| **禁止迁移** | 明确不允许的迁移（黑名单） | MUST 显式列出（这是最有价值的一节） |
| 不变式 | 任意状态都成立的断言 | MUST 可判定 |
| 并发语义 | 同一对象的并发操作是否串行化 | MUST 明确 |

### 2.3 不变量检查（Invariant Checking）

| 步骤 | 动作 | 约束 |
|---|---|---|
| 1 | 为状态机写不变量（如"计数不可为负""总额守恒""权限不升格"） | MUST 可判定 |
| 2 | 把不变量表达为**可执行的断言** | MUST 在 Phase 4 真实运行 |
| 3 | 非法迁移与不变量破坏 **MUST 被捕获**（不得只依赖人工评审） | NEVER 以"路径很短/很少发生"省略 |
| 4 | 捕获即缺陷：先记为缺陷，再决定修实现或修契约 | NEVER 直接改断言掩盖 |

### 2.3a 锚点唯一性（Anchor Uniqueness，★v0.2）

> 来源：真实缺陷回溯 —— 结构定位用了"**最后一个** `)`"这类锚点，语法一旦扩展（尾部追加子句），
> 锚点就漂移到别处，判定随之出错；而错误不是"报错"，而是**静默给出相反结论**。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| 唯一锚点 | 结构定位 MUST 用**配对/唯一锚点**（如"首个 `(` 与其**配对** `)`"） | MUST 配对；MUST NOT 用"最后一个 X" |
| 抗扩展 | 锚点 MUST 在语法/结构扩展后仍指向同一语义位置 | MUST 针对"尾部追加子句"场景断言 |
| 锚点断言 | 每个锚点 MUST 有守护断言（结构变化时立刻红） | MUST 有断言；无断言视为锚点未定义 |
| 失败姿势 | 锚点无法确定时 MUST **不报**（拿不准不报），而非按默认值猜 | MUST 走"拿不准不报" |
| **实体锚点唯一键**（★v0.31） | 定位**实体**（非结构位置）时，锚点 MUST 为**唯一键或其投影**；MUST NOT 用展示文本 / 业务命名 / 别名（归一化差异 ⇒ **无信号失败**）；入参**不足以唯一确定**时，MUST **先收敛到上位且唯一**的锚点（标识符 / 端点 / 组合键），再把剩余判定交给校验项 | 用非唯一锚点 / 直接猜 ⇒ 违反 |

### 2.3b 相邻判定的差异必须显式（★v0.28）

> 来源：真实缺陷回溯 —— 同一状态空间上并存多个判定（终态 / 不阻塞新建 / 可重试），其中两个集合**成员刻意不同**（其一含某状态、另一不含），
> 而注释只写"二者同集合" ⇒ 有人**为对齐而合并** ⇒ 制造新缺陷；同轮另有同一判定在多处散写比较（改一处漏一处）。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| 集合差异即断言 | 语义相邻的两集合成员**不同**时，差异 MUST 由断言钉住（**谁在、谁不在**） | 只断言"差异存在" ⇒ 违反；无断言 ⇒ 违反 |
| **合并禁令** | **MUST NOT** 为"看起来像"而合并两个成员不同的集合（合并即制造新缺陷） | 合并 ⇒ 违反 |
| 谓词不可互替 | 同一状态空间上的多个谓词 MUST 各自登记**判定依据与来源**；MUST NOT 互相替代 | 以一个谓词充当另一个 ⇒ 违反 |
| 关键差异状态断言 | 同时满足/不满足多个谓词的关键状态 MUST 被**显式断言**（例：既属终态、又可重试） | 缺该断言 ⇒ 违反 |
| 谓词变更留痕 | 谓词语义变更 MUST 就地留痕（依据 + 影响面） | 静默改语义 ⇒ 违反 |

### 2.3c 判据时点一致性（★v0.32）

> 来源：真实缺陷回溯 —— 某"是否已存在 / 是否已生效"类判据本属**动作后核验**（核对动作是否真的生效），
> 被前移到**动作前准入**（决定是否允许该动作）⇒ 观测对象在动作前**必然不满足** ⇒ **合法请求被全量拦下**（实测：新增类操作 100% 被拒）。
> 反例（去业务化）：准入规则断言"本次新增的目标标识**未出现**在既有集合中"，而既有集合在动作前**只含既存项**（尚未生效者本就不在其中）⇒ 断言在准入时**恒指向失败**。

| 要求 | 内容 | 硬性约束 |
|---|---|---|
| 时点声明 | 每条判据 MUST 声明其**观测时点**：**动作前准入** 或 **动作后核验** | 未声明 ⇒ 违反 |
| 时点一致 | 判据的观测时点 MUST 与其**约束的动作时点**一致；跨时点复用 MUST **改写判据本身**（MUST NOT 只换调用位置） | 前移 / 后移而不改写 ⇒ 违反 |
| 准入只报必失败 | 动作前准入 MUST **只**报"该动作**必然失败**"的情形（如命名冲突、依赖缺失、权限不足） | 用"可能未生效 / 可能已过时"类判据拒绝 ⇒ 违反 |
| 核验独立登记 | 动作后核验类判据 MUST 有独立入口与留痕，MUST NOT 进入准入判定 | 混入准入 ⇒ 违反 |
| 双向卡口 | 每类判据 MUST 有"**命中**"与"**不误报**"两侧断言（合法请求 MUST 放行） | 缺"不误报"侧 ⇒ 违反 |
| **多段动作的内容指纹锚定**（★v0.78） | 「**先预览 → 人工确认 → 再执行**」这类多段动作 MUST 用**内容指纹**把两段锚在一起：预览回指纹、执行**带指纹**；不一致 ⇒ **MUST 拒执行**并提示重新预览 | 未锚定 ⇒ 两次观测之间**事实可变**（刷新 / 重跑 / 并发改动）⇒ 「**确认过的**」与「**实际执行的**」静默分叉 —— 本节的**跨段**形态（不只是同一判据的时点，而是**两次观测之间**的一致性） |
| **适用对象 / 触发域显式**（★v0.97） | 带适用域的判定（如「仅对主键列」「仅对已提交项」）的**触发前提** MUST 显式，且随判定主体一起搬运 —— 重新实现 / 移植时 MUST NOT 丢失触发前提、退化为「无条件全局判定」；依赖的**外部事实字段语义**（如「当前值 vs 起始值」「下一个 vs 已用」）MUST 显式定义，MUST NOT 望文生义误读 | 丢失触发前提 / 误读字段语义 ⇒ 命中面放大到不适用对象 ⇒ 违反 |

> 与 §2.3b 的关系：§2.3b 讲"同一时点内相邻判定的**差异**必须显式"；本节讲"**跨时点**复用必须先改写判据"。二者 MUST 同时满足。

### 2.4 Forge 式证据链（意图 → 规约 → 验证证据）

需要更强保证时（安全关键、金额/额度、不可逆操作）：

| 步骤 | 动作 | 输出物 |
|---|---|---|
| 1 | 把自然语言意图整理为**可演绎的规约**（前置/后置条件、不变量） | 规约文本 |
| 2 | 对齐实现与规约（模型驱动：先模型后实现） | 对齐说明 |
| 3 | 生成**验证证据**（证明/反例/检查日志） | 证据链条目 |
| 4 | 证据与结论绑定：**无证据不得声称已验证** | 结论 + 证据索引 |

> 现实约束（P11）：安全关键领域（如航空/工业/汽车功能安全标准）下，仅靠"接受生成结果、最少复核"**没有通向认证的路径**；
> 形式化闭环是必要投入，而非可选优化。非安全关键系统可按风险**按需启用**，但一旦启用即适用同一纪律。

## 3. 输入 / 动作 / 输出物

| 项 | 内容 |
|---|---|
| 输入 | 关键流程清单、累积约束台账、规格节点不变量 |
| 动作 | 建台账 → 定义状态机与禁止迁移 → 写不变量 → 表达为断言 → 运行检查 → 需要时走证据链 |
| 输出物 | 约束台账、状态机契约、不变量清单、检查结果、验证证据链 |

## 4. 硬性约束

- **MUST**：A 每条约束有强制手段；B 状态机列出禁止迁移；C 不变量可执行；D 证据先于结论；E 结构定位用**配对/唯一锚点**且有守护断言（★v0.2）；F **实体**定位锚点 MUST 为**唯一键或其投影**，入参不足以唯一确定时 MUST 先收敛到**上位且唯一**的锚点（★v0.31）；G 带适用域的判定，其**触发前提（适用对象 / 触发域）** MUST 显式且随判定主体一起搬运，外部事实字段语义 MUST 显式（★v0.97）。
- **NEVER**：A 静默删除历史约束（只能标记 retired）；B 以"路径短"省略检查；C 改断言掩盖不变量破坏；D 无证据声称"已验证"；E 用"最后一个 X"式**漂移锚点**（★v0.2）；F 锚点不确定时按默认值猜（应**拿不准不报**）（★v0.2）；G 用展示文本 / 业务命名 / 别名作**实体**定位锚点，或锚点不足唯一时按默认值猜（★v0.31）；H 重新实现时丢弃判定触发前提，或望文生义误读外部事实字段语义（★v0.97）。

## 5. 检查清单（Phase 4 退出前逐项打勾）

- [ ] 关键状态机清单已建立（含判定依据：为何它是关键）
- [ ] 每个状态机有：状态集合 / 初始态 / 合法迁移 / **禁止迁移** / 不变量 / 并发语义
- [ ] 不变量已表达为可执行断言并真实运行过
- [ ] 至少验证过 1 条**禁止迁移**能被捕获
- [ ] 约束台账无 `active` 但无强制手段的条目
- [ ] 若启用证据链：每条结论都有对应证据索引
- [ ] 所有结构定位均使用**配对/唯一锚点**，并有针对"尾部追加子句/结构扩展"的守护断言（★v0.2）
- [ ] **实体**定位锚点为**唯一键或其投影**；入参不足唯一时已收敛到**上位且唯一**的锚点（★v0.31）
- [ ] 带适用域的判定，其触发前提（适用对象）已显式且随判定主体一起搬运；外部事实字段语义已显式（★v0.97）

## 6. 反模式

| 反模式 | 现象 | 纠正 |
|---|---|---|
| 只写状态图 | 图里只有合法迁移，没有禁止项 | 补禁止迁移黑名单 |
| 不变量注水 | 写"数据应始终正确" | 改为可判定断言 |
| 断言迁就实现 | 不变量被破坏就改不变量 | 先记缺陷，再决定改哪边 |
| 形式化表演 | 引用了形式化工具但无实际证据 | 走 2.4，证据与结论绑定 |
| 漂移锚点（★v0.2） | 用"最后一个 X"定位，语法扩展后指向别处 | 改配对锚点 + 加守护断言 |
| 触发前提丢失（★v0.97） | 重新实现带适用域的判定时丢了触发条件，退化成对所有对象都判 | 显式声明适用对象，随判定主体一起搬运 |
