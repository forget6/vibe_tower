# 07. 类比复用协议（Analogical Reuse / Feature Cloning）

> 理论支撑：P1–P16（见 `docs/research/research-base.md`）；与"上下文即约束、缺陷分布实证、意图证据"相关的条目见文献基座与 `docs/research/paper-analysis-whitebook.md`。
> 对抗失效：**照抄型复用**——"照着已有功能做一个新的"时，把参照功能的**呈现面**（字段 / 文案 / 提示 / 权限门 / 脱敏 / 规模策略）一并抄过来，
> 或反之**该同构的骨架各写一份**。结果是"**看着对、含义错**"（语义错位）或"改一处漏一处"（双真源）。
> 落地阶段：Phase 0（理解）之后、Phase 1/2（切片与契约）之内；产出物由 Phase 4 的断言与 Phase 3 的关卡消费。

## 1. 目标

| 目标 | 内容 |
|---|---|
| 复用**骨架** | 流程顺序、状态机、守卫与失败语义、审计与通知骨架、接口形状……凡"业务无关或同构"的部分 MUST 复用，MUST NOT 各写一份 |
| 按功能**呈现** | 呈现面（展示哪些字段 / 用什么措辞 / 哪些危险提示 / 哪些权限门 / 是否脱敏 / 长内容如何呈现）MUST **按新功能自身**逐项判定，MUST NOT 沿用参照功能 |
| **差异显式** | 复用与改写的边界 MUST 落成**四分类差异清单**（保留 / 改写 / 新增 / 删除），**逐项**带证据锚与理由；MUST NOT 用"参照 X 即可"代替判定 |

> 一句话：**同构的部分要真同构，不同的部分要显式不同**。

## 2. 核心机制

### 2.1 五步法

| 步 | 动作 | 硬性约束 |
|---|---|---|
| 1 | **选参照**：在功能模型（功能地图）中选出**最相似**的既有功能 | MUST 写**相似度依据**（同状态机 / 同入口 / 同数据通路 / 同失败语义）；相似度不足 ⇒ 不得当模板 |
| 2 | **对齐骨架**：列出**复用面**与**必须保持一致的不变量** | MUST 逐项写"复用哪一处、以哪里为准"（单一真源）；骨架 MUST NOT 复制出第二份实现 |
| 3 | **四分类差异**：`保留（同） / 改写（按新功能） / 新增 / 删除` | MUST 逐项给出：参照位置（证据锚）→ 目标位置 → 判定理由；MUST NOT 留空类（无该类须显式写"无"） |
| 4 | **呈现分离**：流程可同构，**呈现 MUST 按功能** | 展示字段 / 措辞 / 危险提示 / 权限门 / 脱敏 / 长内容规模策略 MUST 逐项**按新功能的功能模型**判定；沿用参照的呈现 ⇒ 违反 |
| 5 | **双向卡口**：把两类结论都写成断言 | ① **相同项**有断言（防漂移）；② **不同项**也有断言（防照抄错位）；只写一侧 ⇒ 违反 |

### 2.2 与既有机制的分工

| 模块 | 关系 |
|---|---|
| `extensions/06-context-learning.md` | 提供**参照候选**（功能地图里"能力 → 状态机/入口/数据通路"）：先理解，才谈复用 |
| `core/01-spec-engine.md` | 差异清单是**规格节点的输入**（改写/新增项 MUST 各自成为可验证节点） |

## 3. 输入 / 动作 / 输出物

| 项 | 内容 |
|---|---|
| 输入 | 新功能需求、功能地图（含参照候选）、既有实现与其契约/用例、边界与不可委托区 |
| 动作 | 1. 选参照并写相似度依据；2. 对齐骨架与不变量；3. 产出四分类差异清单（逐项锚 + 理由）；4. 逐项判定呈现面；5. 把相同项/不同项写成双向断言；6. 未知项显式登记并澄清 |
| 输出物 | 差异清单（项目侧工件）、骨架复用点清单、呈现面判定表、双向断言清单、未知项清单 |

## 4. 硬性约束

**MUST**

- A 复用类改动 MUST 先产出**四分类差异清单**（保留 / 改写 / 新增 / 删除），逐项带"参照锚 → 目标锚 → 理由"。
- B **骨架**（流程顺序 / 状态机 / 守卫 / 失败语义 / 审计与通知骨架）MUST 复用同一真源；MUST NOT 复制出第二份实现。
- C **呈现面**（字段集 / 措辞 / 危险提示 / 权限门 / 脱敏 / 长内容规模策略）MUST 按**新功能**逐项判定并留痕。
- D 断言 MUST **双向**：相同项防漂移、不同项防照抄；差异清单里**每一条改写/新增/删除项** SHOULD 有对应断言或关卡证据。
- E 差异清单 MUST 落成**项目侧工件**（含业务事实）；塔侧只保留方法、模板与判据（可开源）。
- F 未知项（相似度不足、呈现口径未定、边界不清）MUST 显式登记并澄清，MUST NOT 先抄后猜。

**NEVER**

- A **绝不**把参照功能的**呈现面**直接照抄到新功能（字段 / 文案 / 提示 / 权限 / 脱敏）——"看着对、含义错"最难发现。
- B **绝不**用"参照 X 即可"代替逐项差异判定。
- C **绝不**让应当同构的骨架出现两份实现（双真源，改一处漏一处）。
- D **绝不**为了"复用"而顺手重构参照功能（改变动足迹预算）。
- E **绝不**在相似度不足时硬选参照（模板选错 ⇒ 差异清单从第一步就偏）。
- F **绝不**把业务事实写进塔侧产物。

## 5. 检查清单（动手前 / 交付前逐项打勾）

- [ ] 参照功能已选定，且写明**相似度依据**（同状态机 / 同入口 / 同数据通路 / 同失败语义）
- [ ] **骨架复用点**已列明"以哪里为单一真源"（MUST NOT 复制第二份实现）
- [ ] **四分类差异清单**齐备（四类均显式；每项有参照锚 → 目标锚 → 理由）
- [ ] **呈现面**（字段 / 措辞 / 危险提示 / 权限门 / 脱敏 / 长内容规模策略）已按**新功能**逐项判定
- [ ] **双向断言**：相同项有防漂移断言；不同项有防照抄断言（或关卡证据）
- [ ] 差异清单已落到**项目侧工件**（不在对话里、不写进塔）
- [ ] 未知项（相似度 / 呈现口径 / 边界）已显式登记并给出澄清动作

## 6. 反模式

| 反模式 | 现象 | 后果 | 纠正 |
|---|---|---|---|
| 照抄呈现 | 把手模板的字段、文案、危险提示、脱敏策略直接搬来 | 语义错位（"看着对、含义错"），使用者被误导 | 回 §2.1 第 4 步：呈现按新功能逐项判定 |
| 骨架各写一份 | 流程/状态机/守卫复制出第二份 | 双真源，改一处漏一处 | 收敛到单一真源；差异只在"呈现"与"确实不同"处 |
| 无差异清单 | 只说"照着某功能做" | 漏改、漏删、漏新增（评审无从检查） | 产四分类差异清单（逐项锚 + 理由） |
| 参照选错 | 用"像但状态机/失败语义不同"的功能当模板 | 第一步就偏 ⇒ 返工 | 先写相似度依据；不足则不选 |
| 顺手重构参照 | 借复用之名改动参照功能 | 改动足迹失控、回归风险外溢 | 回到预算约束；必要时另立提案 |
